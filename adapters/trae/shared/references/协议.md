# ParallelAgent 文件信箱协议

> 本文件是仲裁者 Skill 与轨道 Skill 的共享协议 reference。
> 两个 SKILL.md 均引用本文件，修改只改这里，勿在各 Skill 中重复定义。

---

## 1. 目录结构

```
docs/协调/
  轨道启动手册.md            # 新会话首条消息永远指向它
  转达/第N轮.md              # 仲裁者只写一次，按轨分节（首部含收尾判据）
  回执/T-X-第N轮.md          # 各轨收工自写（含自检字段）
  快照.md                    # 仲裁者每批后回写：轨/状态/欠账/收回决策
  契约块.md                  # 嵌代码注释形式的最终结论
  交接手册/
    第1版-开轨前.md
    第2版-收回决策.md
    第3版-第二任仲裁者启动.md
  信号/
    dispatch.signal          # 仲裁者→插件：派发指令
    dispatch.ack             # 插件→仲裁者：已派发
    watch.ack                # 插件→仲裁者：回执到齐
    alert.signal             # 插件→仲裁者：超时/卡死告警
    ping.signal              # 仲裁者→插件：查状态
    ping.ack                 # 插件→仲裁者：状态回报
```

**铁律**：回执文件的出现与 mtime 即完成信号——编排器轮询文件系统即可，原则上不读 UI 输出。

## 2. 转达单格式

```markdown
# 第 N 轮转达

## 收尾判据（任一命中即触发收回评估）
- 契约块版本达到 v1.3.0
- T-A/B/C 全部通过验收
- 出现跨轨强依赖
- 总改动行数 > 1500

## 快照
- 当前契约版本：v1.2.3
- 关键文件状态：[简要列表]

## →T-A
[任务边界、目标、文件领地、验收形式]

## →T-B
[任务边界、目标、文件领地、验收形式]

## →T-C
[任务边界、目标、文件领地、验收形式]

## 时序约束
- T-A 完成后 T-B 才能开始（若有依赖）
```

**规则**：仲裁者只写一次转达单，各轨只读自己的 `→T-X` 节，不读别轨节。

## 3. 回执格式

```markdown
# T-X 第 N 轮回执

- 裁决编号引用：[#A.001]
- 完成时点：2026-10-15T10:41:00+08:00
- 证据形式：[文件路径 + 行号 / 测试通过 / 截图]
- 实际改动：[文件列表]
- 待仲裁者实检：[验证清单]

## 自检
- 错误率：x%（最近 N 次工具调用 y 次失败）
- 自评健康度：良好 / 注意 / 警告
- 建议下一轮：继续 / 准备交接 / 立即交接
```

## 4. 契约块格式

契约块是最终结论，嵌在代码注释里，不包含推理过程：

```markdown
<!-- 契约块 v1.2.3 -->
<!-- [#A.001] 模块边界：T-A 负责前端 src/ui/，T-B 负责后端 src/api/ -->
<!-- [#A.002] 接口签名：GET /api/tasks → Task[]，POST /api/tasks → Task -->
<!-- [#A.003] 文件领地：T-A 独占 src/ui/*.tsx，T-B 独占 src/api/*.ts -->
```

裁决编号 `[#A.NNN]` 是稳定引用，回执和转达单都用它。

## 5. 快照格式

```markdown
# 快照

## 当前阶段
并行多轨（阶段 2）

## 契约版本
v1.2.3

## 各轨状态
| 轨 | 状态 | 欠账 | 上轮回执 |
|---|---|---|---|
| T-A | 运行中 | 无 | 第3轮 ✅ |
| T-B | 运行中 | 等待 T-A 接口 | 第3轮 ✅ |
| T-C | 待命 | 无 | 第2轮 ✅ |

## 收回决策（如有）
收回决策（第 5 轮后）：
- 触发判据：剩余子任务正交性（重叠 45%）+ 集成验收需求
- 剩余任务：T-A 收尾 + T-B 接入 + 全局集成测试
- 收回后由谁做：仲裁者亲做（轻量）
```

## 6. 交接手册格式

**角色**：冷启动入口——给新会话/第二任仲裁者用的，不是过程记录。

**只含结构性结论**：
- 当前阶段（奠基/并行/收尾）
- 当前契约版本
- 各轨状态（运行/待命/已销毁）
- 欠账清单（剩余任务）
- 启动方式（新会话首条消息）

**不含**：过程推理、各轨执行细节、对话历史。

**版本管理**：每版保留不覆盖，新会话读最新版。

## 7. 控制信号格式

`dispatch.signal`（仲裁者→插件）：
```json
{
  "batch": 1,
  "actions": [
    { "type": "new", "轨": "T-A", "手册指针": "docs/协调/轨道启动手册.md" },
    { "type": "dispatch", "轨": "T-B", "话术": "读转达第1轮你的→T-B节，执行，写回执" },
    { "type": "dispatch", "轨": "T-C", "话术": "读转达第1轮你的→T-C节，执行，写回执" }
  ]
}
```

**信号体只含轨号 + 轮次 + 文件指针 + 固定话术模板，绝不含任务内容。**

---

## 8. 固定话术模板

控制面绝不传裁决内容，只用以下固定模板：

| 场景 | 话术 |
|---|---|
| 新建轨首条 | `读手册 docs/协调/轨道启动手册.md，你是 T-X，待命` |
| 派发轮次 | `读转达第 {N} 轮你的 →{T-X} 节，执行，写回执` |
| 取消待命 | `本轮无 T-X 任务，待命` |
| 第二任仲裁者启动 | `读交接手册第 N 版 docs/协调/交接手册/第N版-*.md，你是仲裁者 II 世，承接 T-A/B/C 收尾` |
| 第二任分轨启动 | `读交接手册第 N 版 docs/协调/交接手册/第N版-*.md，你是 T-X II 世，承接 T-X 身份` |

## 9. HTTP API

编排器插件监听 `127.0.0.1:9318`，仲裁者 Skill 通过 fetch 调用：

| Endpoint | 入参 | 出参 | 动作 |
|---|---|---|---|
| `POST /dispatch` | `{轨:"T-A", 轮次:1, 话术模板:"派发轮次", 文件指针?}` | `{ok, sid, sent_at}` | 切轨 → 断言 → 注入话术 → 发送 |
| `POST /new` | `{轨:"T-A", 手册指针:"docs/协调/轨道启动手册.md"}` | `{ok, sid, named_at}` | 新建任务 → 注入首条 → 发送 → 落身份表 |
| `POST /watch` | `{轮次:1, 轨:["T-A","T-B","T-C"], timeout_s:1800}` | `{ok, 完成:[...], 未完成:[...]}` | 阻塞监听回执出现+mtime |
| `GET /ping?sid=xxx` | sid | `{状态:"running"/"idle", 任务名}` | 读状态 |
| `POST /delete` | `{sid}` | `{ok}` | CDP 菜单序列删除 |
| `GET /health` | — | `{cdp_alive, port, 轨表}` | 自检 |

**所有 endpoint 入参不含任务内容**——只含轨号、轮次、文件指针、话术模板标识。
