# ParallelAgent 入口分流

> 本文件是 **Layer 1 分流协议的唯一判据源**。
> `parallelagent-solo` 与 `parallelagent-arbiter` 共同引用；修改判据只改这里，各 Skill 不复制阈值。
> 配套：[台账.md](台账.md)（单轨结果记录）、[协议.md](协议.md)（多轨文件信箱）。

---

## 1. 定位与边界

Layer 1 只做三件事：

1. 读用户请求与仓库事实；
2. 按判据判定 L0-L4；
3. 输出分流卡。

**不做**：

- 不写业务代码
- 不建轨道会话
- 不调编排器 HTTP
- 不写转达单/回执
- 不在没有证据时跳级

层级关系：第一层是分流协议，第二层是执行模式（单轨 L0-L3 / 多轨 L4）。分流不常驻、不独立成会话。

---

## 2. 判定顺序

1. 读用户请求，提取目标、范围、验收线索。
2. 只读相关代码/配置/文档，排除“代码里能查到”的未知。
3. 判清晰度（§3）。
4. 判规模（§4）与风险（§5）。
5. 若规模为大，判正交性（§6）。
6. 查分流矩阵（§7），输出分流卡（§8）。
7. 若命中 fail-stop（见 `parallelagent-solo` §9），不得判为可执行，转 L2/L3 或交给用户决策。

---

## 3. 清晰度（5 项检查）

| # | 检查项 | 判定 |
|---|---|---|
| 1 | 目标能否用一句话说清要达成什么 | 否 → 不明确 |
| 2 | 范围与非目标是否明确 | 否 → 不明确 |
| 3 | 输入输出、数据结构、接口形态是否明确 | 否 → 不明确（影响实现时） |
| 4 | 关键异常/边界路径是否明确 | 否 → 不明确（影响验收时） |
| 5 | 能否写出可执行的验收命令或可观察结果 | 否 → 不明确 |

规则：

- 不是 5 项全“否”才算不明确；只要有一项影响范围、验收或安全，就判不明确。
- 不影响实现和验收的空白，**不问**，写进 Assumptions。
- 判定必须给出依据，不能只给结论。

---

## 4. 规模

| 档位 | 判据 |
|---|---|
| 小 | ≤ 2 个文件且 ≤ 50 行；无公开接口/数据结构/配置变更 |
| 中 | 3–10 个文件，或 50–300 行 |
| 大 | > 10 个文件，或 > 300 行，或跨模块/跨层 |

---

## 5. 风险

| 档位 | 判据 |
|---|---|
| 高 | 数据迁移/删除、认证授权、公开 API、生产配置、不可逆操作、跨项目影响 |
| 中 | 依赖升级、构建配置、性能敏感路径 |
| 低 | 文案、样式、局部逻辑、测试补充 |

---

## 6. 正交性（仅大任务）

判 L4 前必须逐条核对以下**强拆条件**：

1. **文件边界正交**：子任务涉及的文件重叠 < 20%
2. **体量足够**：总改动预计 > 500 行
3. **可独立验收**：每个子任务的输出能单独验收
4. **风险不耦合**：一个子任务失败不会污染另一个

等待时间占比 > 30% 可作为加分项，但不作硬门槛。

**任一条不满足 → 不判 L4**，按 L3 单轨立规。

---

## 7. 分流矩阵

| 清晰度 | 规模 | 风险 | 模式 | 计划文档 | 结果记录 | 执行位置 |
|---|---|---|---|---|---|---|
| 明确 | 小 | 低 | **L0 直做** | 无 | 台账（简记/全记） | 当前会话 |
| 明确 | 中 | 低 | **L0 直做** | 无 | 台账（全记） | 当前会话 |
| 明确 | 中/大 | 中/高 | **L3 立规** | 任务卡 | 台账 | 当前会话 |
| 不明确 | 小 | 低/中 | **L1 问清** | 无 | 台账（含问答） | 当前会话 |
| 不明确 | 中/大 | 任意 | **L2 探路 → L3** | 任务卡 | 台账 | 当前会话 |
| 明确/不明确 | 大 | 任意 | **L4 拆轨**（仅当 §6 强拆条件全满足） | 任务卡 + 分流卡 | 回执/快照 | 仲裁者 + 轨道 |

补充规则：

- **明确 + 大 + 不正交** → L3，不强行拆。
- **不明确 + 大** → 先 L2 探路；方案选定后再次判定 L3/L4。
- **L4 只给建议**：用户确认后才开轨；未确认前不调用 `/new`。
- 判定为 L4 但用户拒绝拆 → 回 L3。

## 8. 分流卡与任务卡

### 8.1 分流卡模板

```markdown
分流卡 · 2026-10-26 14:32 · <slug>
- 模式：L1 问清
- 依据：目标明确；验收方式缺失；预估 2 文件 / 30 行；低风险
- 未知项：① 失败提示是否需要可配置 ② 是否记录尝试次数
- 必产：单轨台账（含问答）；无需任务卡
- 下一步：连问 ≤3 个问题 → 直接执行 → 写台账
- 可 override：回复“直接做 / 别问了 / 拆开跑”
```

L4 版本：

```markdown
分流卡 · 2026-10-26 15:10 · <slug>
- 模式：L4 拆轨
- 依据：文件边界正交（重叠 < 10%）+ 总量约 800 行 + 各轨可独立验收
- 建议：3 轨（T-A 前端 / T-B 后端 / T-C 测试）
- 必产：任务卡 + 分流理由；由仲裁者写契约与转达单
- 下一步：用户确认后，仲裁者按现有流程 /new → /wait-ready → /dispatch
- 风险：T-B 改 API 后 T-A 需同步，已在任务卡标注依赖
```

### 8.2 任务卡模板（L2/L3/L4）

```markdown
# <slug> 任务卡

- 分流：L2 / L3 / L4
- 创建：2026-10-26T14:32+08:00
- 原始需求（用户原话摘要）：
- 目标：
- 非目标：
- 未知项：
- 假设（Assumptions）：
- 候选方案 / 选定方案：
- 文件领地：
- 验收条件（可执行/可观察）：
- 证据位置：
- 未决项（Deferred）：
- 升级/降级记录：
- 回滚方式：
```

L4 追加：

```markdown
- 建议拆轨：
- 各轨文件领地：
- 收尾判据：
```

## 9. 用户 override

用户 override 优先于任何自动判定：

| 用户说 | 结果 |
|---|---|
| “直接做 / 别问了” | 强制 L0；未知项全部转 Assumptions/Deferred |
| “先问清楚” | 强制 L1/L2 |
| “拆开跑 / 并行 / 开 N 轨” | 直接进 L4 评估 |
| “按 L3 做” | 强制立规，不拆 |
| “停” | 立即停止当前流程 |

---

## 10. 升级与降级

| 从 | 到 | 触发 | 必须记录 |
|---|---|---|---|
| L0 | L1 | 读代码后发现影响验收的未知 | 台账/任务卡 |
| L0/L1 | L2 | 规模或风险上升；涉及选型/架构 | 任务卡 |
| L1/L2 | L3 | 方案选定，需要契约与验收条件 | 任务卡 |
| L3 | L4 | §6 强拆条件全满足 + 用户同意 | 分流卡 |
| L4 | L3 | 用户拒绝拆 / 可用轨不足 / 依赖过强 | 分流卡 |
| 任意 | fail-stop | `parallelagent-solo` §9 任一命中 | 台账/任务卡 |

规则：

- 允许直接跳到目标层级（如 L0 发现应为 L3），但必须写清证据，不得无理由跳级。
- 不允许静默降级：从 L3 降回 L0 必须说明为什么风险已消除。
- 一次只处理一次升级/降级，不连环改判；用户 override 除外。

---

## 11. 与仲裁者 §4 的关系

- 仲裁者的 L4 判定直接引用本文件 §6/§7，不再复制阈值。
- 仲裁者只保留两件事：奠基阶段判据（契约/边界/骨架是否就绪）与决策输出格式。
- 单轨的 L0-L3 流程见 `parallelagent-solo`。
- 任何阈值调整只改本文件。

---

## 12. 输出约束

1. 分流卡必须在首轮回复中给出，不能先做再补判定。
2. 判定依据至少两条（例如清晰度 + 规模/风险）。
3. 判 L4 必须列出强拆条件的逐条核对结果。
4. 判 L0/L1 必须说明“为什么不需要任务卡”。
5. 所有“未知项”必须落到 Assumptions、Deferred 或提问三者之一，不能悬空。
