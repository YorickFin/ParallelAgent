# ParallelAgent 单轨台账

> 本文件是 **单轨（L0-L3）结果记录的唯一规范**，`parallelagent-solo` 引用。
> 定位：**结果记录**，不是过程日志。
> 硬口径：**零计划文档 ≠ 零记录。计划可以省，结果必须留痕。**

---

## 1. 定位与边界

| 项 | 结论 |
|---|---|
| 是什么 | 结果记录：谁要的、改了什么、怎么证明、结论如何、怎么回滚 |
| 不是什么 | 过程日志、推理记录、PRD、聊天记录备份 |
| 与 git 的分工 | git 记录 diff；台账记录 **意图 + 验收 + 结论**，即 git 覆盖不了的部分 |
| 与多轨回执的分工 | 单轨台账只覆盖 L0-L3；L4 用转达/回执/快照，不双写 |
| 写入方式 | 只追加；不修改历史；记错追加“更正”条目引用原 ID |

---

## 2. 目录与命名

```
.parallel-agent/
  单轨/
    台账/
      YYYY-MM.md            # 按月一个文件（Q1=B）
    任务卡/
      <slug>.md             # L2/L3/L4 才有
    证据/
      S-YYYYMMDD-NNN/
        test-output.txt     # 可选：命令输出、截图说明
```

规则：

- **按月分文件**：当月条目写入 `YYYY-MM.md`；跨月新建下月文件，不在旧文件续写。
- **ID**：`S-YYYYMMDD-NNN`，全局唯一；NNN 在月内递增。
- 台账与任务卡入 git；证据以文本为主，截图等二进制按项目仓库规则处理。
- `.parallel-agent/信号/` 仍只由插件使用，单轨不写信号文件。

---

## 3. 简记 vs 全记

判定标准只有一条：**这次改动会不会改变外部可观察行为**。

| 类型 | 适用 | 必填字段 |
|---|---|---|
| 简记 | 注释、文案、格式、纯测试补充、依赖小版本 | 需求、改动、证据、结论 |
| 全记 | 行为、接口、数据、配置、可观察逻辑 | 以下全部字段 |

全记额外字段：目标/非目标、问答、未决/风险、回滚。

## 4. 条目模板

### 4.1 简记

```markdown
## S-20261026-003 · 2026-10-26 14:32 · L0
- 需求：修正登录页文案错别字（用户原话：“把‘登入’改成‘登录’”）
- 改动：src/ui/LoginForm.tsx（+2/-2），commit a1b2c3d
- 证据：diff 已核对；无运行时行为变化
- 结论：通过
```

### 4.2 全记

```markdown
## S-20261026-004 · 2026-10-26 15:10 · L1
- 需求（原话）：登录失败要提示剩余尝试次数（“至少告诉我还剩几次”）
- 目标 / 非目标：只改前端提示；不改后端锁定策略
- 问答：Q1 是否需要可配置 → A 先硬编码 5 次；Q2 是否记录尝试 → A 不记录
- 改动：src/auth/login.ts、src/ui/LoginForm.tsx（+42/-8），commit d4e5f6a
- 证据：`pnpm test auth` → 12 passed；空密码用例返回 400
- 结论：通过
- 未决 / 风险：锁定阈值 5 次未与产品确认
- 回滚：git revert d4e5f6a
```

### 4.3 更正条目

不改历史，追加一条引用原 ID：

```markdown
## S-20261026-005 · 2026-10-26 16:02 · 更正
- 更正对象：S-20261026-004
- 更正内容：证据命令应为 `pnpm test:auth`，原命令名笔误
- 结论：不影响原判定
```

## 5. commit 关联（Q2=D 混合）

| 改动类型 | 规则 |
|---|---|
| 行为变更（接口/数据/配置/可观察逻辑） | 与代码同一个 commit；台账条目必须写 commit hash |
| 非行为变更（文案/注释/格式/测试补充） | 允许 `未提交` 条目；会话结束前回填 commit hash；确实无法提交时标注 `未提交（原因）` |
| 批次提交 | 一个 commit 可对应多条台账；台账更新必须包含在同一 commit 中 |
| 未提交条目 | 下一次单轨会话启动读取时优先处理（补提交或说明原因） |

约定：

- commit message 建议格式：`<type>: <subject> [S-YYYYMMDD-NNN]`
- 一条台账只能对应一个 commit（或未提交状态）
- 不得事后伪造 commit hash；找不到就写 `未提交`

---

## 6. 证据规则

**只接受可核对证据**：

- 命令 + 退出码/输出摘要（如 `pnpm test auth` → 12 passed）
- 文件路径 + 行号
- diff 片段（用于纯文案/格式改动）
- 截图/录屏（引用 `证据/<ID>/` 下的文件）

**不接受**：

- “已测试”“应该没问题”“本地验证过了”这类自述
- 无法复现的口头结论
- 与改动无关的旧测试结果

---

## 7. 会话启动读取

单轨 Skill 启动时：

1. 读当月台账文件。
2. 读上月台账中标记 `未决` / `未提交` 的条目。
3. 检查是否有同文件冲突、未决项、未回填 commit。
4. 若有同文件未决项，先向用户提示，再决定是否继续。

台账因此也是**下一个会话的冷启动入口**，比聊天记录可靠。

---

## 8. 与多轨回执的关系

| 场景 | 记录载体 |
|---|---|
| L0-L3 单轨改动 | 单轨台账 |
| L4 多轨执行 | 转达单 + 回执 + 快照 |
| L4 收回后由单轨收尾 | 收尾部分写单轨台账，并引用 `收回决策` 与相关回执 |
| 第二任仲裁者交接 | 交接手册，不写单轨台账 |

---

## 9. doctor 校验（Q3=B：只告警）

`parallelagent doctor` 检查项目层台账，失败只告警，不阻断、不改变退出码：

1. `.parallel-agent/单轨/台账/` 目录是否存在
2. 当月 `YYYY-MM.md` 是否存在
3. 最近 N 条是否包含 `需求` / `改动` / `证据` / `结论`
4. 是否存在 `未提交` 条目需要回填 commit

---

## 10. 完成定义

单轨任务同时满足以下条件，才允许汇报“完成”：

1. 改动完成且未越界
2. 验收证据可核对
3. 台账条目已写入，字段完整
4. commit 关联符合 §5
5. 未决项已记录或已解决
6. L3 额外要求：任务卡验收条件逐条满足

缺任何一项，只能说“已改完，待补记录/待验证”。
