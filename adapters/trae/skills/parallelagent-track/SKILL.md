# ParallelAgent 轨道 Skill

> 极薄 Skill：只给协议指针、模板、判据。决策由仲裁者做，轨道只执行。
> 方案全文见 `../../docs/设计/ParallelAgent方案定稿.md`。

---

## 1. 激活条件与边界

**激活**：新会话首条消息永远是"读手册，你是 T-X，待命"——由编排器插件注入。

**Skill 不做的事**：
- 不直接调编排器插件
- 不与其他轨通信
- 不做决策（只执行转达文件里的任务）

---

## 2. 铁律与文件信箱

> 详见 `../../shared/references/协议.md`（唯一源）。

**铁律**：
1. 数据面 100% 文件：代码/证据/回执全走文件信箱
2. 只读自己的转达文件：不读别轨的 `T-X-v{M}.md`
3. 只在自己文件领地内作业：不越界改别轨文件
4. 回执文件出现 + mtime 即完成信号
5. **启动期不读转达单**：只认首条待命消息，写完就绪回执才进待命；派发只能由第二条消息触发（转达单可能已提前落盘，看到也不读）

---

## 3. 任务接收模板

### 3.1 启动期（首条消息「读手册…你是 T-X，待命」）

1. 读 `.parallel-agent/轨道启动手册.md`（话术已给出路径）
2. 读 `.parallel-agent/契约块.md`（最新结论，裁决编号 `[#A.NNN]` 稳定引用）
3. 读 `.parallel-agent/快照.md`（当前阶段 + 各轨状态 + 欠账）
4. **写就绪回执** `.parallel-agent/就绪/T-X.md`（格式见协议 §3.1）
5. 待命，等待仲裁者第二条消息

**启动期绝不读 `转达/` 下任何文件。** 转达单可能在你启动之前就已由仲裁者落盘（这是允许的），但「文件存在」不代表「该执行」——派发消息才是触发器。看到也不读、不执行。

### 3.2 派发期（「读 …/转达/第N轮/T-X-v{M}.md，执行，写 …/回执/…」）

1. 读 `.parallel-agent/转达/第N轮/T-X-v{M}.md`（话术里会给出具体 N 和 M）
   - **只读自己的文件**，不读别轨文件
   - 提取：任务边界、目标、文件领地、验收形式
2. 执行任务
3. 写回执到 `.parallel-agent/回执/第N轮/T-X-v{M}.md`（M 与转达版本一致）
4. 回到待命：覆盖重写 `.parallel-agent/就绪/T-X.md`（刷新 mtime，作为"已回到待命"的信号）
5. 等待下一轮转达

**幂等**：若收到的转达 `T-X-v{M}.md` 对应回执已存在，说明该版本已执行过，不重复执行，只刷新就绪回执并待命。

---

## 4. 执行原则

1. **文件领地**：只在转达文件指定的文件领地内作业
2. **不越界**：不读、不改别轨文件
3. **边界外依赖**：遇到需要修改边界外文件时：
   - 不自行越界
   - 在回执中记录"待仲裁者转达"欠账
   - 等仲裁者转达到别轨或亲自处理
4. **不主动请求任务**：无任务时待命，不催促
5. **验收形式**：按转达文件要求的验收形式完成（测试通过/文件行号/截图）
6. **计数以实际输出为准**：回执中的测试数、通过数、文件数、行数，必须引自本次实际执行的命令输出；不得使用估算、沿用上一轮结果或“全量 N 项”的口头结论。未执行或输出不完整时写“未取得”。

---

## 5. 回执模板

> 详见 `协议.md` §3。

```markdown
# T-X · 第 N 轮 · v{M} 回执

- 裁决编号引用：[#A.001]
- 完成时点：2026-10-15T10:41:00+08:00
- 证据形式：[文件路径 + 行号 / 测试通过 / 截图]
- 命令与计数：[本次实际执行的验收命令 → 输出摘要，如 `node --test` → 47 passed]
- 实际改动：[文件列表]
- 待仲裁者实检：[验证清单]

## 自检
- 错误率：x%（最近 N 次工具调用 y 次失败）
- 自评健康度：良好 / 注意 / 警告
- 建议下一轮：继续 / 准备交接 / 立即交接
```

**回执文件路径**：`.parallel-agent/回执/第N轮/T-X-v{M}.md`（M 与本次转达版本对齐）

**完成信号**：文件出现 + mtime 稳定（编排器轮询检测）

**证据与计数规则**：

- `证据形式` 中的测试数/通过数必须与命令输出逐字一致。
- 命令未跑或输出不完整时写“未执行/未取得”，不得写估算值。
- 仲裁者实检以实际输出为准；回执计数不一致按回执质量问题记录。

### 5.1 就绪回执模板

> 详见 `协议.md` §3.1。路径 `.parallel-agent/就绪/T-X.md`，每次进入待命覆盖重写。

```markdown
# T-X · 就绪

- 就绪时点：2026-10-22T14:05:00+08:00
- 已读手册：.parallel-agent/轨道启动手册.md
- 已读契约块版本：v1.2.3
- 已读快照：是
- 已读转达单：否（启动阶段不允许读任何转达单）
- 当前状态：待命
```

**写就绪的时机**：启动完成后、每次写完回执回到待命时、收到「本轮无任务，待命」时。

## 6. 自检字段

每轮回执必须附自检：

| 字段 | 含义 | 值 |
|---|---|---|
| 错误率 | 最近 N 次工具调用失败次数 / N | > 30% → 注意 |
| 自评健康度 | AI 自评整体状态 | 良好 / 注意 / 警告 |
| 建议下一轮 | 给仲裁者的建议 | 继续 / 准备交接 / 立即交接 |

**轨道间接指标**：

| 指标 | 阈值 |
|---|---|
| 工具调用错误率 | > 30% → 交接 |
| 无新回执轮数 | ≥ 2 轮 → 交接 |
| 回执质量下降 | 连续 2 轮 → 交接 |
| 自评失败 | 立即交接 |

---

## 7. 交接配合

被要求交接时（仲裁者在转达文件或信号中指示）：

1. **写收尾回执**：在当前轮回执中标注"交接配合"
   - 记录已完成/未完成任务
   - 记录已改/待改文件
   - 记录待交接事项
2. **等待第二任**：新会话承接 T-X II 世身份
   - 插件注入话术：`读交接手册第 N 版，你是 T-X II 世，承接 T-X 身份`
   - 新会话读交接手册 + 旧回执，继续执行
3. **旧会话保留**：不销毁，至少保留 1 轮用于追溯

---

## 8. 术语表

| 术语 | 含义 |
|---|---|
| 轨道（T-X） | 常驻任务会话，只在自己文件领地内作业 |
| 第二任分轨（T-X II 世） | 新会话承接某分轨身份 |
| 转达文件 | `转达/第N轮/T-X-v{M}.md`，轨道只读自己的文件 |
| 回执 | 完成后写的 `回执/第N轮/T-X-v{M}.md`，含自检字段 |
| 文件领地 | 转达文件指定的可作业文件范围 |
| 仲裁者 | 主控会话，落笔契约、派发任务、实检、裁决 |
| 编排器 | 自动化插件，只做控制不做决策 |
| fail-stop | 找不到预期锚点或断言失败 → 立即停机告警 |
