# ParallelAgent 单轨 Skill

> 极薄 Skill：只给流程、判据指针、模板与闸门。
> 分流判据见 `../../shared/references/分流.md`（唯一源；已安装时位于 `~/.trae-cn/shared/references/分流.md`）。
> 台账规范见 `../../shared/references/台账.md`（已安装时位于 `~/.trae-cn/shared/references/台账.md`）。
> 方案见仓库内 `adapters/trae/docs/实施/v2.0.0+/ParallelAgent第二期实现规划.md`（仅开发参考）。

---

## 1. 激活与边界

**激活**：

- 用户提出需要改代码/文档/配置的开发请求；
- 且没有明确说“拆开跑 / 并行 / 分轨 / 开 N 轨”。

**不激活**：

- 纯问答、查资料、研究、评审；
- 用户明确要求拆轨（由 `parallelagent-arbiter` 承接）。

**Skill 不做的事**：

- 不建轨道会话、不调编排器 HTTP；
- 不写转达单 / 回执 / 就绪 / 信号文件；
- 不做多轨的拆分、收回、交接决策；
- 不自动提交、不自动推送。

---

## 2. 铁律

1. **零计划文档 ≠ 零记录**：L0/L1 可以不建任务卡，但必须写台账条目。
2. **单轨不依赖插件**：停掉编排器，L0-L3 仍可完整执行。
3. **自动分流不自动开轨**：L4 只写任务卡与分流卡，用户确认后才移交仲裁者。
4. **证据不接受自述**：只认命令输出、文件行号、diff、截图。
5. **fail-stop**：验收写不出、改动越界、高风险无口径、无法记录 → 停，不猜。
6. **台账只追加**：不修改历史；更正用新条目引用原 ID。
7. **用户 override 最高**：`直接做 / 别问了 / 拆开跑 / 停` 优先于任何自动判定。

---

## 3. 入口：先分流

收到请求后：

1. 读 `../../shared/references/分流.md`。
2. 按 `分流.md` §3-§7 判定 L0-L4。
3. 输出分流卡（模板见 `分流.md` §8.1）。
4. 按模式进入本 Skill §4-§8。

分流卡必须包含：模式、至少两条依据、未知项、必产文档、下一步。不得先做再补判定。

---

## 4. L0 直做（明确 + 小/中 + 低风险）

**适用**：文案、样式、局部逻辑、单文件小修、测试补充。

1. 读相关文件，确认改动边界。
2. 在回复中写一句意图与验收口径（不落任务卡）。
3. 执行改动，不碰无关文件。
4. 自检：跑相关命令 / 核对 diff。
5. 写台账条目（简记或全记，见 `台账.md` §4）。
6. 汇报：改了什么、证据是什么、台账 ID 是什么。

**禁止**：写 PRD/spec/任务清单；建轨道；写交接手册。

---

## 5. L1 问清（不明确 + 小）

**适用**：方向清楚，但有一两个影响验收的空缺点。

1. 先读代码/配置，排除“代码里能查到”的问题。
2. 生成候选问题，按影响排序，取 ≤3 个。
3. 一次只问一个，按 §9 格式。
4. 每个答案立即写入台账草稿（最终并入台账）。
5. 问完（或用户说停）后直接执行。
6. 写全记台账，含问答。

**上限**：≤3 问；超过仍未解决 → 升级 L2，不硬问。

---

## 6. L2 探路（不明确 + 中/大）

**适用**：需求概念清楚，但方案、边界或可行性未定。

1. 只读：代码、依赖、现有实现、相关文档。
2. 给 2-3 个可选方案，说明代价、风险、放弃的理由。
3. **不写业务码**；除非用户明确说“先做个 spike”。
4. 产出任务卡（模板见 `分流.md` §8.2），记录：目标、非目标、未知项、假设、候选方案、选定方案、验收条件。
5. 用户确认方案后 → L3；若满足强拆条件 → L4。

**硬约束**：探路阶段最多只改任务卡/台账，不改业务代码。

---

## 7. L3 立规（明确 + 中/大 + 中/高风险，或 L2 收敛后）

**适用**：改动大、风险高、需要先定契约再动手。

1. 写任务卡：目标、非目标、文件领地、接口/数据约束、验收条件、回滚方式。
2. 用户确认任务卡（至少确认验收条件与非目标）。
3. 按任务卡执行，不越界。
4. 每完成一个可验证单元，写一次台账（允许批量，但不允许最后补记）。
5. 全部验收条件逐条核对，写最终结论。
6. 执行中发现强拆机会且用户同意 → L4。

**与多轨的关系**：L3 任务卡与 L4 任务卡同格式；升级时不需要重写。

---

## 8. L4 移交（拆轨）

1. Layer 1 输出分流卡 + 任务卡（含建议拆轨与文件领地）。
2. 用户确认“拆”。
3. 把任务卡路径交给 `parallelagent-arbiter`；仲裁者按 §4 复核奠基并走现有流程。
4. 单轨在此停止，不执行任何业务改动，不写多轨回执。

**未确认前禁止**调用 `/new` / `/dispatch`。

---

## 9. 提问规范

| 规则 | 内容 |
|---|---|
| 总配额 | L1 ≤ 3 问；L2/L3 ≤ 5 问；一次会话累计不超过 5 问 |
| 节奏 | **一次只问一个** |
| 每题结构 | `问题` + `为什么重要（一句）` + `推荐项及理由` + `2-5 个互斥选项` 或 `≤5 词短答` |
| 推荐 | 必须给推荐项，并说明依据（项目约束、风险、常见做法） |
| 禁止问 | 代码/配置里能查到的；纯风格偏好；纯技术选型（除非阻塞功能或验收） |
| 优先级 | 范围 > 安全/数据 > 用户体验 > 技术细节 |
| 答案处理 | 立即写回任务卡/台账，不留在对话里 |
| 提前停止 | 关键歧义已解决，或用户说“停/别问了/直接做” |
| 超额处理 | 写入 Deferred，标注风险，交用户决定，不硬问 |

题目格式：

```markdown
**问题：** 登录失败提示里是否需要显示剩余尝试次数？
（为什么重要：这决定要不要改后端返回结构，影响验收用例。）

**推荐：** 选项 B —— 只在前端提示，不改接口，风险最小。

| 选项 | 说明 |
|---|---|
| A | 后端返回剩余次数，前端展示 |
| B | 前端只提示“还有机会”，不改接口 |
| C | 不提示次数，只提示失败 |
| 短答 | 用 ≤5 词给出你的答案 |

回复选项字母即可；也可以说“推荐”或直接给短答。
```

## 10. fail-stop 触发条件

以下任一命中，**立即停止执行**：

1. 验收条件写不出（无法验证）。
2. 需要改动的文件超出任务卡/意图声明范围。
3. 涉及数据迁移/删除、认证授权、公开 API、生产配置，且用户未给明确口径。
4. 有两种合理实现，后果不同，且没有可辩护的默认值。
5. 无法写台账（不知道改了哪些文件 / 没有可核对证据）。
6. 用户明确说“停”。

处理：

- 在配额内 → 问清楚再继续；
- 配额用尽 → 升级 L2/L3，或交用户决策；
- **禁止**“先改完再问”“先猜一个再说”。

---

## 11. 完成定义

同时满足以下条件，才允许汇报“完成”：

1. 改动完成且未越界。
2. 验收证据可核对。
3. 台账条目已写入，字段完整。
4. commit 关联符合 `台账.md` §5。
5. 未决项已记录或已解决。
6. L3 额外要求：任务卡验收条件逐条满足。

缺任何一项，只能说“已改完，待补记录/待验证”。

---

## 12. 台账

- 规范见 `../../shared/references/台账.md`。
- 目录：`.parallel-agent/单轨/台账/YYYY-MM.md`（按月）。
- ID：`S-YYYYMMDD-NNN`。
- 所有 L0-L3 改动都必须写；L4 不写单轨台账。
- 会话启动时先读当月台账 + 上月未决/未提交条目。

---

## 13. 会话退化与冷启动

| 指标 | 阈值 | 动作 |
|---|---|---|
| 工具调用错误率 | > 30% | 准备新会话 |
| 重复输出 | ≥ 3 次 | 立即新会话 |
| 用户连续指出错误 | ≥ 2 次 | 立即新会话 |
| 无法说清当前改动范围 | 出现即触发 | 立即新会话 |

冷启动：

1. 当前会话写/更新任务卡（若还没有，至少写“当前状态 + 下一步”）。
2. 汇总最近台账条目 ID。
3. 新会话首条消息：`读 .parallel-agent/单轨/任务卡/<slug>.md 与最近台账，继续 <slug>`。
4. 不写交接手册——任务卡 + 台账就是单轨冷启动入口。

## 14. 自检汇报模板

```markdown
本轮单轨自检：
- 分流：L0 / L1 / L2 / L3
- 改动范围：<文件列表>
- 证据：<命令 + 结果 / 文件行号>
- 台账：S-YYYYMMDD-NNN
- 未决项：无 / <列表>
- 健康度：良好 / 注意 / 警告
```

---

## 15. 与其他 Skill 的边界

| Skill | 关系 |
|---|---|
| `parallelagent-arbiter` | 只在 L4 移交后接手；读单轨任务卡，不重复提问 |
| `parallelagent-track` | 单轨不接触；轨道只由插件注入启动 |
| 编排器插件 | 单轨不调用；L4 由仲裁者调用 |

---

## 16. 术语

| 术语 | 含义 |
|---|---|
| 单轨 | 单会话执行模式，覆盖 L0-L3 |
| 分流卡 | Layer 1 的判定输出 |
| 任务卡 | L2/L3/L4 的计划与约束文件 |
| 单轨台账 | L0-L3 的结果记录 |
| 简记 / 全记 | 台账的两种深度 |
| 证据 | 可核对的命令/行号/diff/截图 |
| fail-stop | 无法校验时立即停机 |
