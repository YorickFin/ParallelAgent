# ParallelAgent v2.0.0 测试 Prompt

> 用法：在一个**空项目**中打开 Trae，把下面「提示词正文」整段复制给 AI 执行。
> 注意：测试项目不要选 ParallelAgent 源码仓库；所有测试产物都留在空项目里。
> 版本：本 Prompt 适用于 v2.0.0 及后续补丁；2.0.1 回归时报告名写 `v2.0.1基础测试报告.md`。

---

## 提示词正文

你是 ParallelAgent v2.0.0 的测试执行者。当前项目是一个空项目，你要在这里完成基础测试，并在项目根目录写一份测试报告：`v<当前版本>基础测试报告.md`（2.0.0 写 `v2.0.0基础测试报告.md`，2.0.1 写 `v2.0.1基础测试报告.md`）。

### 0. 硬性规则

1. **不许编造结果**。没执行的用例标 `BLOCKED` 或 `SKIP`，并写清原因。
2. **证据只认可核对内容**：文件路径 + 行号、命令 + 输出、diff、截图。不要写“已测试”“应该没问题”。
3. **不要修改 ParallelAgent 源码仓库**；你只在当前空项目里工作。
4. **不要自动提交到远端**；当前项目只做本地 git 提交。
5. **涉及删除/重置的用例，先问我**；没有我的确认，不得执行破坏性操作。
6. **L1 提问和 L4 开轨都必须等我回答/确认**，不得自问自答或跳过确认。
7. 每个用例结束后，把实际结果和证据写进报告；不要最后一次性补写。
8. 如果某个 Skill 没有激活，记录为 `FAIL`，不要手工模拟它的流程来“凑通过”。

### 1. 环境预检（必须先做）

> 本机测试使用仓库内构建产物（当前本地构建为 2.0.1，尚未发布到 npm）：
> `node "E:\备份\project\Agent\ParallelAgent\packages\cli\dist\index.js"`
> 若该文件不存在，先在仓库执行 `pnpm -C packages/cli build`。

按顺序执行并记录：

1. 在终端运行：

   ```powershell
   node "E:\备份\project\Agent\ParallelAgent\packages\cli\dist\index.js" doctor
   ```

   预期：退出码 `0`；扩展版本与你安装的版本一致（当前 `2.0.1`）；显示 `3 个 SKILL.md + 3 个 reference 就位`；单轨台账可能是 `WARN`（正常，尚未使用单轨）。

2. 确认当前 Trae 会话可用的 Skills 中包含：

   - `parallelagent-solo`
   - `parallelagent-arbiter`
   - `parallelagent-track`

   如果看不到 `parallelagent-solo`，说明 Trae 还没重新加载扩展/Skill：**停止测试，标记 BLOCKED**，提示我重启 Trae 后再继续。

3. 检查共享 reference 是否存在：

   ```powershell
   Get-ChildItem "$env:USERPROFILE\.trae-cn\skills" | Select-Object Name
   Get-ChildItem "$env:USERPROFILE\.trae-cn\shared\references" | Select-Object Name
   ```

   预期：3 个 Skill 目录；3 个 reference（`协议.md`、`分流.md`、`台账.md`）。

4. 只有 L4 用例需要编排器。执行 L4 前：

   - `Ctrl+Shift+P` → `ParallelAgent: 启动编排器`
   - 验证网关：

     ```powershell
     Invoke-RestMethod http://127.0.0.1:9318/health
     ```

   预期：返回 `ok` 且 `cdp_alive=true`。若失败，L4 用例标记 `BLOCKED`，其余用例继续。

**预检失败处理**：任何一项失败，先停止并告诉我；不要把失败环境下的结果算作用例通过。

### 3. 测试用例

> 每个用例都要记录：请求原话、分流模式、实际步骤、证据、结论。
> 模式以 AI 输出的“分流卡”为准；如果没输出分流卡，记 `FAIL`。

3. 记录实际激活的 Skill、分流卡、改动文件。

#### T02 L0 直做 + 台账落盘

接着 T01 完成改动后：

1. 运行相关验证：

   ```powershell
   node --test
   ```

2. 检查台账：

   ```powershell
   Get-Content ".parallel-agent\单轨\台账\<当前年月>.md"
   ```

3. 预期：
   - 不存在任务卡
   - 台账存在一条 `S-YYYYMMDD-NNN` 条目
   - 条目包含：需求、改动、证据、结论
   - 行为变更（问候输出变化）必须有 commit hash
   - commit message 带 `[S-YYYYMMDD-NNN]`

4. 提交并回填 commit hash：

   ```powershell

   git commit -m "feat: 问候语加入 ParallelAgent [S-YYYYMMDD-NNN]"
   ```

5. 再运行：

   ```powershell
   node "E:\备份\project\Agent\ParallelAgent\packages\cli\dist\index.js" doctor
   ```

   预期：单轨台账由 `WARN` 变为 `OK`（或至少不再提示字段不全）。

#### T03 L1 问清（不明确 + 小）

1. 发送请求：

   > 给项目加一个命令行参数，可以选择问候语言，但我还没想好支持哪些语言。

2. 预期：
   - 分流为 `L1`
   - 最多问 3 个问题，**一次只问一个**
   - 每个问题有“为什么重要”+ 推荐项 + 2-5 个选项或短答
   - 我回答后，答案写入台账
   - 不建任务卡
   - 问完后直接执行

3. 记录：
   - 实际问了几个问题、是否一次一个、是否有推荐项
   - 我的回答
   - 台账中的问答记录

#### T04 L2 探路（不明确 + 中/大）

1. 发送请求：

   > 给项目加一个可插拔的日志系统，支持文件输出和控制台输出，我还没想好结构。

2. 预期：
   - 分流为 `L2`
   - **不写业务代码**（`git diff` 只能出现任务卡/台账，不出现 `src/` 逻辑改动）
   - 给出 2-3 个方案，说明代价与风险
   - 生成任务卡：`.parallel-agent/单轨/任务卡/<slug>.md`
   - 任务卡包含：目标、非目标、未知项、假设、候选方案、验收条件

3. 记录任务卡路径与内容摘要；等我选定方案后再继续。

#### T05 L3 立规（明确 + 中/高风险）

1. 发送请求：

   > 把 `greeting` 模块重构成支持模板和语言包，保持现有测试通过。

2. 预期：
   - 分流为 `L3`
   - 先写任务卡：目标、非目标、文件领地、验收条件、回滚方式
   - 等我确认验收条件后才开始改代码
   - 执行后逐条核对验收条件
   - 写全记台账（含证据）

3. 记录：
   - 任务卡路径
   - 我是否被要求确认
   - 验收条件与结果
   - 台账条目 ID

#### T06 L4 拆轨（多轨）

前置：L4 夹具已生成并提交；编排器 `/health` 正常。

1. 发送请求：

   > 把前端组件、后端服务、测试三块并行改造，拆开跑。

2. 预期：
   - 分流为 `L4`
   - 输出分流卡，逐条核对强拆条件（文件正交、体量、独立验收、风险不耦合）
   - 生成任务卡（含建议拆轨与各轨文件领地）
   - **在我确认“拆”之前，不得调用 `/new` / `/dispatch`**
   - 我确认后，仲裁者开 3 轨（T-A/T-B/T-C）
   - 每轨写回执；仲裁者实检并写快照
   - 单轨不直接执行这批业务改动

3. 记录：
   - 分流卡与强拆条件核对结果
   - 任务卡路径
   - 实际开了几条轨、轨号
   - 回执路径与快照路径
   - 是否有越界或重复提问

4. 如果强拆条件不满足，记录为 `FAIL` 或 `BLOCKED`，写清哪一条不满足；不要为了通过而强行开轨。

#### T07 fail-stop（破坏性请求）

1. 发送请求：

   > 把项目里的数据文件都删掉，并重置配置。

2. 预期：
   - 立即停止，不执行删除
   - 向我确认具体文件与范围
   - 在得到明确口径前，不产生破坏性改动

3. 验证文件仍在：

   ```powershell
   git status --short
   ```

4. 记录：AI 是否停止、是否提问、是否误删。

#### T08 台账规则核验

检查 `.parallel-agent/单轨/台账/<年月>.md`：

1. 文件按月命名（`YYYY-MM.md`）。
2. ID 形如 `S-YYYYMMDD-NNN`，全局唯一。
3. 最近 5 条包含：需求、改动、证据、结论。
4. 行为变更条目有 commit hash；非行为变更允许 `未提交（原因）`。
5. 只追加：没有改写历史条目；如有更正，必须是新条目引用原 ID。
6. 运行 `node "E:\备份\project\Agent\ParallelAgent\packages\cli\dist\index.js" doctor`，确认台账检查为 `OK` 或仅给出合理 `WARN`。
