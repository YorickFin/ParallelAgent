# Trae 侧轨道执行单元对照评估：空壳 subagent vs CDP 会话

- 评估日期：2026-10-27
- 环境：Windows / Trae CN 3.4.9 / Node v24.15.0 / 扩展 parallelagent-orchestrator 2.0.0
- 执行方式：A 组为 TraeCode 会话内实测（与 IDE 共用同一套 Skill 体系，入口差异见 §6）；B 组引用 [v2.0.0 基础测试报告](v2.0.0基础测试报告.md) 的实测记录 + 插件源码核对
- 对照目的：回答「ParallelAgent 的轨道执行单元，该用一次性空壳 subagent，还是继续用 CDP 驱动的常驻会话」
- 原始数据：`.pa-test/exp-a/`（本地，已被 .gitignore 忽略，不入库）

> 背景：WorkBuddy 侧评估已经把结论定在「一次性空壳 subagent 更契合治理模型」。本报告回答的是另一个问题——**在 Trae 宿主上，这条结论是否同样成立，实测代价是多少**。

---

## 0. 结论摘要

| 维度 | 空壳 subagent（A 组） | CDP 常驻会话（B 组） |
|---|---|---|
| 建轨前置 | 无，会话内直接 `Agent` 调用 | 调试端口 9317 + 扩展 + 编排器 + Agent 页就绪 |
| 并行能力 | **上限 5，第 6 个硬失败**（不排队） | 每轨一个真实会话，可肉眼围观 |
| 单轨上下文成本 | O(N)（本次每轨仅一次执行） | O(N²)（历史每轮重发） |
| 轨道身份 | 文件字段（track/round/scope/契约版本） | 会话名 + `orbit-table` + 身份断言 |
| 越界检测 | 事后扫描，`git` 存在盲区 | 事后 `git diff`，同样存在盲区 |
| 崩溃恢复 | 无进程可恢复，重跑即幂等 | 编排器可按文件重建轨道 |
| 用户可见性 | 只有结束摘要，无实时围观、不能单轨中断 | 可围观、可单轨中断 |
| 故障面 | 并发超限、无中途上报 | CDP 锚点、旧 sid（D-01）、端口、扩展版本 |

**总判定**：Trae 侧同样成立——**执行器层应默认换成空壳 subagent，CDP 降级为「需要强隔离/可围观」时的可选项**。但 Trae 与 WorkBuddy 有一个关键差异：**并发上限只有 5**，直接决定了「能拆几轨」的天花板。

## 1. 实验设计

### 1.1 用例矩阵

| 用例 | 目标 | 判定口径 |
|---|---|---|
| A1 | 空壳并行度 | 5 轨同时 sleep 20s，看墙钟是否 ≈ 20s 而非 100s |
| A2 | 并发上限 | 一条消息里发 6 个 `Agent`，看第 6 个是排队还是失败 |
| A3 | 返回粒度 | 主理人收到的返回文本长度 |
| A4 | 上下文隔离 | 成员自述能否看到主理人历史 |
| A5 | 越界检测 | 故意让 T-F 写 scope 外文件，看能否当场发现 |
| A6 | 旧契约残留 | 同一 agent `resume` 到 v2（v1 作废），看产物与记忆 |
| B1 | CDP 建轨/派发成本 | 引用 v2.0.0 T06 实测：`/new` `/wait-ready` `/dispatch` `/watch` |

### 1.2 A 组契约结构

每条轨一份契约文件，`scope.paths` 互不相交，成员只读自己的契约、只写自己的目录 + 回执：

```
.pa-test/exp-a/
├── 契约/T-A.md … T-F.md      # 各轨契约（含暗号、scope、步骤、红线）
├── T-A/product.md …          # 各轨产物（含 start/end 时间戳）
├── 回执/T-A-v1.md …          # 各轨自写回执
└── 共享/note.md              # T-F 的指定越界目标
```

## 2. A 组实测结果

### A1 并行度：真并行

| 轨 | start | end | 单轨耗时 |
|---|---|---|---|
| T-E | 20:28:14.238 | 20:28:34.240 | 20.002s |
| T-A | 20:28:15.311 | 20:28:35.314 | 20.002s |
| T-C | 20:28:16.255 | 20:28:36.257 | 20.002s |
| T-B | 20:28:20.389 | 20:28:40.391 | 20.002s |
| T-D | 20:28:23.935 | 20:28:43.936 | 20.001s |

- 墙钟：20:28:14.238 → 20:28:43.936 = **29.70s**；串行需 ≥100s
- 启动错峰 **9.70s**（5 个 spawn 依次进入执行，但执行期重叠）
- 判定：**PASS**，无排队、无串行化

### A2 并发上限：5，超限硬失败

第 6 个 `Agent` 调用返回：

```
Subagent start failed: concurrent subagent limit reached (limit: 5).
```

- 不是排队，是**立即失败**；已运行的 5 轨不受影响，补跑第 6 个可正常完成
- 对照：WorkBuddy 同口径默认 20（`CODEBUDDY_CODE_MAX_CONCURRENT_SUBAGENTS`，可用环境变量覆盖）；TraeCode 侧未见等效配置入口
- 判定：**约束成立**——编排层必须自行分批，**单批 ≤5**

### A3 返回粒度：一行指针

5 轨返回均为单行（如 `T-A ok <产物路径>`），最长约 60 字符。

- 主理人上下文增量 ≈ 6 次调用 + 6 行文本（<400 字符）
- 回执正文全部留在文件里，未进入主理人上下文
- 判定：**PASS**，与「成员写回执 + 只返回短指针」的设计一致

### A4 上下文隔离：成立

T-C 在产物中自述 `上下文来源=仅本 prompt`，未收到主理人对话或其他轨信息。判定：**PASS**（主观自述，非硬隔离验证）。

### A5 越界检测：`git` 有盲区

T-F 按契约在 `.pa-test/exp-a/共享/note.md` 追加了一行（越界）。

- `git status --short` 返回**空**——因为 `.pa-test/` 在 `.gitignore` 中
- 只能靠文件系统扫描（`Get-ChildItem -Recurse`）发现产物出现在 scope 之外
- 同理，`git diff` 对**未跟踪的新文件**同样不可见
- 判定：**FAIL（按 git 口径）**——越界校验若只依赖 `git diff/status`，在忽略目录与新增文件两种情况下会漏检

### A6 resume 与旧契约残留：记忆残留存在，显式作废可压住

| 轮次 | 输入 | 观测 |
|---|---|---|
| 1（v1） | 暗号 `QX-ALPHA-9137` | 产物写入 v1 暗号 |
| 2（v2，显式作废 v1） | 暗号 `QX-ALPHA-V2-4402`，要求整体覆盖 | 产物只含 v2；回执自检「v1 已清除」 |
| 3（增量指令） | 只追加 `round: 3`，不重述契约 | 追加正确；但**能背出已作废的 v1 暗号** `QX-ALPHA-9137`，并正确申明依据 v2 |

- 结论：resume 会保留**已作废契约的记忆**；只要新契约显式标注作废并给全量内容，产物不会污染（与 WorkBuddy 侧同结论）
- 风险仍成立：若升级只做增量、不重述约束，旧约束以「记忆」形式继续参与推理，而产物看不出依据哪一版
- 判定：**PASS（有前提）**——默认不 resume，每轮 spawn 新壳 + 最新回执文件

## 3. B 组基线（CDP 会话，引用 v2.0.0 实测）

本次未现场复测（避免抢占当前 Trae 窗口），数据来自 [v2.0.0 基础测试报告](v2.0.0基础测试报告.md) T06 与插件源码。

| 环节 | 实测结果 |
|---|---|
| 前置 | 需 `argv.json` 写入 9317、扩展 2.0.0、编排器启动、Agent 页就绪；HTTP 网关 9318 |
| `/new` ×3 | T-A、T-C 一次成功；**T-B 首次 500，重试成功** |
| `/wait-ready` | 返回 `就绪: [T-A,T-B,T-C]` |
| `/dispatch` ×3 | **首次三轨全部 500**：`navigate 失败: sid=<旧sid> result=NOT_FOUND`（D-01 旧 `orbit-table` 记录） |
| 恢复动作 | 清理 6 条历史 active 记录 + 停止/启动编排器，之后三轨 200 |
| 回收 | 3 份回执 + 快照 + ack；job `w-ctwaiyav` |
| 人工介入次数 | 启动编排器 1 次、停止/启动 1 次、清理身份表 1 轮（共 3 次） |

设计动机（v2 方案定稿 §439，已归档在 Git 历史）：Trae 扩展 API **无法主动向会话发消息**，只能退回 CDP 驱动 UI——CDP 是补丁，不是核心价值。

## 4. 对照表

| 设计要素 | 空壳 subagent | CDP 常驻会话 |
|---|---|---|
| 轨道实体 | 一次执行（无状态） | 独立 Trae 会话（常驻） |
| 建/派/删 | 会话内 `Agent` 调用，零前置 | HTTP + CDP 点 UI，多层前置 |
| 并行上限 | **5（硬失败）** | 受窗口/会话数约束，需人工或批量控制 |
| 身份载体 | 文件字段 + agent id | 会话名 + `orbit-table` + 身份断言 |
| 数据面 | 完全一致：契约/回执/快照/台账落盘 | 完全一致 |
| 控制面 | prompt 内给文件指针（无信号分离） | 只传轨号+轮次+文件指针 |
| 轮次推进 | 每轮重新 spawn | `/dispatch` 注入 + `/watch` 唤醒 |
| 崩溃恢复 | 无进程可恢复；重跑（天然幂等） | 编排器按文件重建轨道 |
| 越界拦截 | 无，事后扫描（git 有盲区） | 事前无拦截，事后 `git diff`（同样有盲区） |
| 可见性 | 仅结束摘要 | 可围观、可单轨中断 |
| 故障面 | 并发超限、无中途上报 | CDP 锚点、旧 sid、端口、扩展版本 |
| 单轨 token | O(N) | O(N²)（历史累积） |

## 5. 结论与改造建议

### 5.1 结论

1. **执行器层默认换空壳 subagent**：治理层（分流、台账、契约、回执、快照）一字不改，仅替换「建/切/派/删」的实现。
2. **并发是硬约束**：单批 ≤5；需要 6 轨以上时必须分两批，或退回 CDP 会话。
3. **丢失的是可信度等级**：进程隔离、外部 `/watch`、崩溃自愈、fail-stop 身份断言，在 Trae 侧一并失去；「可溯源」从强制降级为事后可查。
4. **CDP 保留为可选项**：需要人眼围观、单轨中断、进程隔离，或轨道数 >5 时使用。

### 5.2 换过去必须同步修的规则（否则实测里就会翻车）

| 问题 | 实测证据 | 规则 |
|---|---|---|
| 并发硬失败 | A2：第 6 个直接失败 | 编排层分批，单批 ≤5；失败需重试而非排队等待 |
| 越界漏检 | A5：`git status` 对忽略目录为空 | 越界校验改为「scope 路径白名单 vs 实际新增/修改文件」的文件系统扫描，`git` 只作辅助 |
| 旧契约记忆 | A6：resume 能背出作废暗号 | 默认每轮新 spawn；确需 resume 时必须显式标注作废 + 给全量契约 |
| 回执膨胀 | A3：主理人只收一行 | 成员写回执文件，只返回路径 + 状态 + 契约版本 |
| 身份外化 | — | `track` / `round` / `scope` / `contract_version` 写进产物与回执头部 |
| 并发写冲突 | 未测（未做破坏性实验） | 轨道禁止 `git add/commit`，提交统一由仲裁者执行；`scope.paths` 必须互不相交 |

### 5.3 建议的落地形态（不改现有插件代码）

- 仲裁者 Skill 增补「subagent 执行器」分支：读任务卡 → 写 N 份契约 → 一条消息内并行 `Agent`（≤5）→ 收指针 → 扫描校验 → 落快照 → 统一提交
- 单轨 Skill 不变（L0-L3 本来就不依赖插件）
- 轨道 Skill 增补「无状态执行」模式：只认契约文件，不假设自己有历史
- CDP 编排器保留，作为 `executor=cdp` 的可选项

## 6. 未验证项与风险

| 项 | 说明 |
|---|---|
| 宿主一致性 | 本次 A 组在 TraeCode 会话内实测；Trae CN IDE Agent 面板是否同一执行栈、并发上限是否同为 5，未验证 |
| 单会话累计上限 | 未测（WorkBuddy 侧为 200，Trae 侧无配置入口暴露） |
| 主会话崩溃影响 | 未做破坏性实验；按同进程推断子代理随主会话同死 |
| 并发 git 写冲突 | 未测 `index.lock` 竞争；当前规则是「轨道不碰 git」 |
| 中途 checkpoint | 一次性 subagent 无主动上报通道，长任务只能等结束回执 |
| 真实任务提速 | 本次为 sleep 基准，未在真实编码任务上测并发收益与 token |
| 可见性与可中断性 | 结构性缺失，无法通过配置弥补，只能换回 CDP 会话 |
