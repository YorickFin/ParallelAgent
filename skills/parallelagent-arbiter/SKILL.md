# ParallelAgent 仲裁者（arbiter）

## 依赖

- `~/.parallel-agent/references/协议.md`
- `~/.parallel-agent/references/分流.md`
- `~/.parallel-agent/templates/`
- `~/.parallel-agent/能力档案/<host>.md`（全局）
- `.parallel-agent/能力档案.md`（可选项目覆盖）

## 工作流

### 0. 能力档案校验（每次 L4 预检）

1. 读全局档案；不存在 → 走 `§首次探测` 三选一
2. 比对 `schema_version` / `host_version` / 探测项清单
3. 不一致 → 询问用户：立即重测 / 暂用旧档案 / 其它
4. 合并项目覆盖（仅工作区策略类字段）
5. 取 `max_concurrency`（未知按 1）与 `max_mode`
6. `max_mode` 不含 L4 → 停止，改为单轨并告知用户

### 1. 决策与文档

1. 按 `分流.md` 核对强拆条件，写**分流卡**
2. 写**任务卡**（目标/非目标/未知项/验收/文件边界）
3. 写**交接手册**（开轨前版，含重跑方式）
4. **用户确认后才继续**：确认对象是「验收条件 + 非目标 + 文件边界」三件套；用户原话含「拆开跑」只等于确认拆分，不抵扣这三项

### 2. 写契约

- 每轨一份，路径 `.parallel-agent/契约/第N轮/T-X-vM.md`
- 用 `templates/契约.md`；`scope` 互不相交
- 契约**自足**：不依赖轨道记得任何历史
- 写**转达**（只放指针）

### 3. 分批派发

- `batch = min(轨道数, max_concurrency)`
- 一条消息内并行 spawn 该批；**不把超限交给宿主排队**
- 每条轨的 prompt 只给三样：契约路径、回执路径、返回格式（一行指针）
- 宿主 `nested: no` → 不得要求轨道再派子代理

### 4. 收集与校验

1. 收齐返回（一行指针即可）
2. 按 `协议.md` §6 做**越界扫描**（文件系统为准，git 仅辅助）
3. 校验：回执齐全且 `kind`/必填字段完整、`contract_version` 一致、产物落在 `scope` 内；缺字段即回执无效，要求轨道重写同一版本回执（不代写）
4. 越界 ≥1 → 收回该轨，记入快照

### 5. 实检与收尾

1. 运行验收命令，记录输出
2. 按生命周期判据做本轮判定（继续下一轮 / 收回 / 收尾路由），结论写入快照
3. **提交产物**：`git add` 产物与契约/转达/回执 → commit（message 带任务 ID），记下 hash A
4. 写**快照**（各轨状态、越界结果、实检结论、判定结论、待处理、`handover_version`；提交字段填 hash A，不得写「待提交」）
5. **出交接手册新版**（`交接手册/第N版-收尾.md`：阶段改收尾、轨道状态改实际结果、勾掉欠账、写 HEAD=A 与重跑方式）；未出新版即收尾未完成
6. 写台账摘要条目（L4），回填 hash A
7. **提交元文件**：`git add` 快照/交接手册/台账 → commit（message 引 hash A）；该提交 hash 不写进任何文档，避免自含循环

## 硬规则（来自实测，违反即视为缺陷）

| 规则 | 原因 |
|---|---|
| 单批 ≤ `max_concurrency` | 超限硬失败，不排队 |
| 轨道禁止 `git add/commit` | 并发 `index.lock` 冲突 |
| 越界只认文件系统扫描 | `git` 看不见忽略目录与未跟踪文件 |
| 默认不 resume；每轮新壳 + 最新回执 | resume 保留已作废契约记忆 |
| 回执由轨道写，只收一行指针 | 防止仲裁者上下文被回执撑爆 |
| 任务粒度必须单次执行可完成 | 无中途上报通道 |
| 契约头部必须有 `contract_version` | 产物可追溯 |

## 首次探测

档案不存在时询问用户三选一：

1. **立即初始化测试**：说明预计 spawn 次数 → 确认后按 P1-P6 执行 → 写全局档案（标 `confidence: 实测`）
2. **触发 L4 时再测试**：本次跳过，下次 L4 再问
3. **其它**：用户自由输入，按其要求执行，不擅自探测

探测全程由 Agent 按步骤执行，**不写脚本**。探测在临时目录进行，测完清理。

若 `~/.parallel-agent/hosts/<host>.md` 已存在且 `host_version` 与当前一致，可直接建议用户采用该预置实测值（`confidence: 实测`），仍需用户确认后才复制为能力档案。

## fail-stop

- 找不到契约或版本不一致 → 停止派发
- 越界无法确认归属 → 停止并提问
- 轨道连续两次失败 → 不再自动重试，转人工

## 回复规范

- 不粘贴回执正文，只给指针与结论
- 每轮输出自检摘要：批次、失败率、重试次数、越界命中、版本错配、上下文压力
