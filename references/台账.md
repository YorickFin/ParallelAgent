# 单轨台账规则

台账是单轨改动的唯一留痕。L0-L3 每次都写；L4 只写摘要，主载体是回执与快照。

---

## 1. 文件与 ID

- 文件：`.parallel-agent/单轨/台账/YYYY-MM.md`（按月建，跨月新建）
- 条目 ID：`S-YYYYMMDD-NNN`（当日三位序号，从 001 起，不复用）；与分流卡共用同一当日序列，跳号属正常（序号可能被 `分流卡/S-YYYYMMDD-NNN.md` 占用）
- 只追加：**不得修改或删除历史条目**

---

## 2. 条目字段

| 字段 | 必填 | 说明 |
|---|---|---|
| ID | 是 | `S-YYYYMMDD-NNN` |
| 时间 | 是 | ISO 时间 |
| 模式 | 是 | L0-L3（L4 摘要写 L4） |
| 需求 | 是 | 用户原话或一句话概括 |
| 目标 / 非目标 | 是 | 非目标可为「无」 |
| 改动 | 是 | 文件清单 + 行数概览 |
| 证据 | 是 | 命令与输出摘要（测试、构建、diff） |
| 结论 | 是 | 完成 / 部分完成 / 放弃 |
| 未决 | 否 | 遗留项 |
| 回滚 | 否 | 撤销方式（git revert / 文件还原） |
| commit | 是（行为变更必填） | 提交 hash |

---

## 3. 顺序要求

行为变更条目遵循「先提交代码 → 再写台账并提交」：

1. 改代码
2. 跑验证，收集证据
3. `git commit`（message 带条目 ID）
4. 写台账条目，回填真实 commit hash
5. 提交台账

原因：台账里不能出现猜测的 hash。

---

## 4. 检查清单

| 检查 | 判定 |
|---|---|
| 文件名符合 `YYYY-MM.md` | 否 → 不合格 |
| ID 唯一且递增 | 否 → 不合格 |
| 最近条目字段齐全 | 缺必填 → 不合格 |
| 行为变更条目有 commit | 缺 → 不合格 |
| 历史条目未被修改 | 有 → 不合格（应新建更正条目） |

---

## 5. L4 摘要条目

L4 在台账写一条摘要即可：

- ID、模式 `L4`、任务卡路径、轨号清单
- 快照路径与 commit hash
- 结论：完成 / 部分完成

明细以回执与快照为准，台账不复制回执正文。
