# ParallelAgent v3 协议

本文件定义 `.parallel-agent/` 下所有文件的字段、命名与校验规则。**Skill 只引用本文件，不复制正文。**

---

## 1. 目录结构

```
.parallel-agent/
├── 能力档案.md              # 可选：项目级覆盖项（宿主能力在全局）
├── 分流卡/S-YYYYMMDD-NNN.md
├── 单轨/
│   ├── 任务卡/<slug>.md
│   └── 台账/YYYY-MM.md
├── 契约/第N轮/T-X-vM.md
├── 转达/第N轮/T-X-vM.md
├── 回执/第N轮/T-X-vM.md
├── 快照.md
└── 交接手册/第N版-<事件>.md
```

规则：

- 轨号 `T-A`…`T-Z`；一轮内不复用
- `vM` 为契约版本（`v1` 起），与轮次无关：同一轮可以是 `v2`
- 所有文件 UTF-8，Markdown + YAML frontmatter
- `.parallel-agent/` 下全部是**元文件**（流程留痕），不属业务产物；产物提交与元文件提交必须分开，首次使用不要把元文件混进业务提交

---

## 2. 文件清单与落笔权

| 文件 | 落笔权 | 说明 |
|---|---|---|
| 分流卡 | 仲裁者 / 单轨 Skill | 入口判定，L1+ 必产 |
| 任务卡 | 仲裁者 / 单轨 Skill | L2/L3 必产；L4 由仲裁者写 |
| 台账 | 单轨 Skill / 仲裁者 | 只追加，不修改历史条目 |
| 契约 | **仅仲裁者** | 落盘后才允许派发 |
| 转达 | 仅仲裁者 | 只含指针，不含任务内容 |
| 回执 | **仅轨道** | 成员自写；主理人不代写 |
| 快照 | 仅仲裁者 | 汇总 + 实检结论 |
| 交接手册 | 仅仲裁者 | 冷启动入口，只写结构结论 |

**禁止**：轨道修改契约、转达、快照；仲裁者代写回执。

---

## 3. 通用头部字段

所有文件以 frontmatter 开头，`kind` 必填：

| kind | 附加必填 |
|---|---|
| `分流卡` | `mode`（L0-L4）、`date` |
| `任务卡` | `task_id`、`mode` |
| `契约` | `track`、`round`、`contract_version`、`scope`、`receipt` |
| `转达` | `track`、`round`、`contract_version`、`pointers` |
| `回执` | `track`、`round`、`contract_version`、`result`、`artifacts` |
| `快照` | `round`、`batch` |
| `交接手册` | `version`、`stage` |

`result` 取值：`ok` / `failed` / `blocked`（与轨道返回行一致）。

`artifacts` 使用**项目根相对路径**（不以盘符开头），保证跨机器可复核。

## 4. 各文件字段定义

### 4.1 契约

```yaml
---
kind: 契约
track: T-A
round: 1
contract_version: v1
scope: [".parallel-agent/...", "src/a/**"]
receipt: .parallel-agent/回执/第1轮/T-A-v1.md
created_at: <ISO>
---
```

正文必含：

- 任务目标与**非目标**
- 产物路径（每个文件一行）
- 验收口径（命令或判据）
- 红线（禁止读取的路径、禁止运行的命令）
- 执行步骤（可被一次执行完成）

规则：

- `scope` 是越界校验的唯一依据；各轨 `scope` 不得相交
- 契约内容必须**自足**：轨道不继承任何历史
- 版本升级改变 `scope` / 验收 / 产物时必须升版本，并在正文首行标注「vN 作废」与全量新内容

### 4.2 转达

```yaml
---
kind: 转达
track: T-A
round: 1
contract_version: v1
pointers: [".parallel-agent/契约/第1轮/T-A-v1.md"]
---
```

- 只允许出现**指针**（文件路径），不得出现任务正文
- `pointers` 至少含契约路径

### 4.3 回执

```yaml
---
kind: 回执
track: T-A
round: 1
contract_version: v1
result: ok
artifacts: ["src/a/sum.js", "test/a/sum.test.js"]
---
```

正文必含：

- 依据版本（`contract_version`）
- 产物路径清单（与 `artifacts` 一致）
- `artifacts` 只列 `scope` 内**交付产物**，不含回执自身与任何 `.parallel-agent/` 元文件；`scope` 里出现回执路径只表示「允许写」，不等于计入产物
- 自检：是否只读契约、是否运行禁命令、是否越界
- 未决项（无则写「无」）

### 4.4 快照

```yaml
---
kind: 快照
round: 1
batch: 3
handover_version: 1
---
```

正文必含：

- 各轨状态（ok / failed / blocked / 已收回）
- 越界扫描结果（命中清单，无则写「无」）
- 实检结论（测试命令与结果）
- 判定结论（继续下一轮 / 收回 / 收尾路由）与产物提交 hash（必须是已存在的真实提交，不得写「待提交」）；元文件提交 hash 不入文档，由提交信息的「引 A」承载
- `handover_version`（必须等于 `.parallel-agent/交接手册/` 下最新版号；不一致视为收尾未完成）
- 待处理项

### 4.5 交接手册

```yaml
---
kind: 交接手册
version: 1
stage: 奠基|并行|收尾
---
```

**每次阶段切换、收回决策、收尾都必须出新版并保留旧版；未出新版即视为收尾未完成。**

正文必含：当前阶段、当前 `contract_version`、各轨状态、欠账清单、**重跑方式**（spawn 哪些契约、批次大小）、冷启动首条消息模板。不含过程推理。

## 5. 命名规范

- 分流卡 / 台账 ID：`S-YYYYMMDD-NNN`（当日三位序号，从 001 起）；两者**共用同一当日序列**，因此台账出现跳号（序号被分流卡占用）属正常，不是漏记
- 任务卡：`<kebab-slug>.md`，与任务主题一致
- 契约 / 转达 / 回执：`第N轮/T-X-vM.md`，三处同名
- 交接手册：`第N版-<事件>.md`（`开轨前` / `收回决策` / `新任仲裁者启动`）
- 台账：`YYYY-MM.md`，按月建文件

---

## 6. 越界扫描算法

**不做全量树扫描，只扫本轮变更。**

1. **取基线**（spawn 前）
   - 顺序硬约束：先落盘全部分流卡 / 任务卡 / 交接手册 / 契约 / 转达，**然后**取基线，**最后** spawn；顺序颠倒会把仲裁者自己的文档算进差集
   - 有 git：记录 `git status --porcelain` 输出
   - 无 git：记录 `scope` 内目标文件的哈希与 mtime
2. **取结果**（spawn 后）
   - 有 git：再次 `git status --porcelain`；**另需**扫描被 `.gitignore` 忽略的目录（git 看不见）
   - 无 git：重新计算哈希
3. **求差集**：本轮新增 / 修改 / 删除的文件
4. **白名单**：各轨 `scope` + `.parallel-agent/回执/**` + `.parallel-agent/快照.md` + `.parallel-agent/交接手册/**`
5. **判定**：差集内出现白名单外文件 → 越界，记入快照并收回对应轨
6. **注意**：`git diff` 看不到未跟踪新文件与被忽略目录，**不能单独作为依据**

---

## 7. 契约版本规则

- 初版 `v1`；`scope` / 产物 / 验收变更 → 升版本
- 升版本必须**全量重述**，并显式写「vN-1 作废」
- 回执必须记录实际依据的 `contract_version`
- 仲裁者实检时，版本不一致即视为回执无效，需重跑

---

## 8. 校验清单（仲裁者每轮执行）

| 检查项 | 判定 |
|---|---|
| 各轨是否都有回执 | 缺 → 该轨未完成 |
| 回执 `kind` 与必填字段是否齐全 | 缺 → 回执无效，要求轨道按契约重写同一版本回执 |
| 回执 `contract_version` 是否等于当前契约 | 不等 → 回执无效 |
| `artifacts` 是否落在 `scope` 内 | 否 → 越界 |
| 快照是否覆盖全部轨 | 缺 → 快照不完整 |
| 快照 `handover_version` 是否等于交接手册最新版 | 不等 → 收尾未完成 |
| 台账条目是否含证据与结论 | 缺 → 台账不合格 |
| 是否有轨道执行了 git 写操作 | 有 → 违规，仲裁者接手提交 |
