# ParallelAgent v3 方案设计

- 状态：草案（待评审）
- 日期：2026-10-27
- 配套：[ParallelAgent v3 生命周期治理方案](ParallelAgent%20v3%20生命周期治理方案.md)（何时拆 / 何时收 / 收回后谁做 / 何时交接 / 怎么自检）
- 前置结论来源：`test-docs/评估/WorkBuddy多Agent能力评估.md`、`test-docs/评估/Trae侧轨道执行单元对照评估.md`

---

## 0. 一句话

把 ParallelAgent 收敛成**一套协议 + 一套模板 + 三个 Skill**：治理规则全部用文件表达，轨道执行交给宿主自带的 subagent，首次运行靠**能力自检**把宿主差异填进「能力档案」，之后所有分支都读档案。宿主缺什么就降级或明确拒绝，不再写宿主专用插件。

---

## 1. 背景

v2 的三件套是「仲裁者 Skill + 轨道 Skill + 编排器插件（CDP + HTTP + 信箱 watch）」。两轮评估得到的结论：

1. **CDP 是补丁不是价值**：它存在的原因是 Trae 扩展 API 无法主动向会话发消息。换一个自带 subagent 的宿主，这个补丁就没有存在必要。
2. **常驻会话会引入第二事实源**：轨道「记得」上一版契约，产物却看不出依据哪一版；且每轮重发历史，成本 O(N²)。
3. **空壳 subagent 与治理模型同构**：一次执行只带当前契约文件，成本 O(N)，身份靠文件字段（track / round / scope / contract_version）。
4. **换上 subagent 后暴露的硬约束**（Trae 实测）：
   - 并发上限 **5**，超限**硬失败不排队**
   - 越界检测用 `git status/diff` 会漏（忽略目录、未跟踪新文件）
   - `resume` 会保留**已作废契约的记忆**
   - 无中途上报通道，只能拿结束回执
   - 丢失进程隔离、单轨围观/中断、崩溃自愈

因此 v3 的方向不是「换个插件」，而是**把执行器抽象出来，用宿主原生能力实现**。

---

## 2. 目标与非目标

### 2.1 目标

- 治理层（分流、台账、契约、回执、快照）**零改动**可跨宿主复用
- 换宿主只需填一张**能力档案**，不写代码
- 首次运行自动/半自动探测宿主能力，结果落盘并可审计
- 任何能力缺失都有明确的**降级或拒绝**路径，不静默假设
- 加固能力（隔离、围观、中断）保留为可选执行器，不绑定主路径

### 2.2 非目标

- 不做「一个 skill 零适配到处跑」——执行器差异必须显式参数化
- 不做宿主 UI 驱动（CDP）作为默认路径
- 不追求探测宿主全部能力，只探测会改变编排决策的少数几项
- 不引入运行时服务（HTTP 网关、守护进程）作为必需组件

## 3. 架构：三层 + 可移植性分档

| 层 | 内容 | 可移植性 |
|---|---|---|
| **治理层** | L0-L4 分流判据、单轨台账、多轨契约/回执/快照、命名与校验规则 | 纯文本，跨宿主通用 |
| **执行器层** | 建轨、派发、收工、唤醒 | 按能力档案参数化 |
| **加固层** | 进程隔离、单轨围观/中断、崩溃重建、身份断言、中途通知 | 不可移植；宿主原生提供，或自建可选执行器 |

架构图：

```
用户请求 ──▶ 入口分流（L0-L3 单轨 / L4 多轨）
                │
                ├─ L0-L3：当前会话 ──▶ 单轨台账
                │
                └─ L4：仲裁者会话
                          │ 读「能力档案」选择执行器
                          ├─ 默认：subagent 执行器（宿主原生）
                          └─ 待定：加固层执行器（隔离 / 围观 / 中断）
                                     │
                          文件信箱 ◀──┴──▶ 轨道（一次执行 / 常驻会话）
```

## 4. 能力档案（Capability Manifest）

### 4.1 位置与生命周期

能力是**宿主的属性**（应用 + 版本 + 权限模式），不是项目的属性，因此默认放全局：

- 全局路径：`~/.parallel-agent/能力档案/<host>.md`，每宿主一份
- **不放 Skill 安装目录**：`~/.trae-cn/skills` 这类目录在升级/卸载时会被清空，档案会随之丢失
- 项目覆盖（可选）：`.parallel-agent/能力档案.md` 仅在需要覆盖时存在，只允许覆盖「工作区策略」类字段（工作区信任、权限模式、是否有 git、忽略规则），不得覆盖宿主机能力
- 生命周期：首次运行探测一次，写入全局；**宿主版本或模板结构版本变化即失效**，只重测一次，不随项目重复探测
- **校验时机**（读文件比字段，成本极低）：

| 时点 | 行为 |
|---|---|
| Skill 会话内首次激活 | 读一次档案，标记是否有效，避免 L4 中途才发现 |
| **每次 L4 预检** | 必做：比对 `schema_version` / `host_version` / 探测项清单，不一致则提示三选一 |
| 用户显式要求 | 强制重读并复核 |

- L0-L3 **不做**校验（单轨不依赖子代理能力）
- 归属：**档案由 Agent 写，CLI 只读不写**；CLI 的安装状态另存 `install-state.json`（§7.4）
- 必备元数据：

```yaml
host: Trae CN
host_version: 3.4.9
probed_at: 2026-10-27T20:40:00+08:00
probe_cost: 8 spawns        # 探测消耗的子代理次数
schema_version: 1           # 对应「能力档案-模板」的结构版本
confidence: 实测            # 实测 / 自述 / 未验证
stale_after_version_change: true
```

**可信度声明**：`confidence` 标记本档案的来源等级，降级决策一律按最低可信度处理——`未验证` 等同于缺失（走降级矩阵），`自述` 不得用于并发类判断。

### 4.2 字段表

**静态字段**（读自身工具清单即可，零成本）

| 字段 | 含义 | 取值示例 |
|---|---|---|
| `subagent.tool` | 子代理工具名与参数形态 | `Agent(subagent_type, prompt)` |
| `subagent.nested` | 子代理能否再派子代理 | `no` |
| `subagent.resume` | 能否按 agent id 续跑 | `yes` |
| `subagent.background` | 是否支持后台执行 + 唤醒/回传通道 | `yes / no` |
| `sandbox.shell` | 子代理能否执行命令 | `yes` |
| `sandbox.fs_write` | 子代理能否写文件 | `yes` |
| `vcs.git` | 是否有 git 可用 | `yes` |
| `skills.install_path` | Skill 安装路径 | `~/.trae-cn/skills` |
| `skills.trigger` | 触发方式 | `描述自动激活 / 命令` |

**动态字段**（必须在沙箱里真跑一次）

| 字段 | 含义 | 探测方法 |
|---|---|---|
| `subagent.max_concurrency` | 同批最大并发，超限行为 | 2 → 4 → 8 逐级同时拉起，记录首个失败报错原文 |
| `subagent.result_granularity` | 返回文本是否截断/压缩 | 让子代理返回 2000 字，比对长度 |
| `subagent.max_total_per_session` | 单会话累计上限 | 成本高，默认 `unknown`，不主动测 |
| `fs.guard` | 宿主是否拦截越界写 | 沙箱内让子代理写 scope 外文件，看是否报错 |
| `isolation.process` | 同进程 / 独立进程 | 子代理自报 pid 与宿主比较 |

### 4.3 探测用例（全部在沙箱，测完清理）

| 编号 | 用例 | 观测 | 产出字段 |
|---|---|---|---|
| P1 | 单子代理写文件 + 执行 `sleep 1` | 是否成功 | `sandbox.fs_write` / `sandbox.shell` |
| P2 | 同时拉起 2 / 4 / 8 个 | 第几个开始失败、报错原文 | `subagent.max_concurrency` |
| P3 | 要求返回 2000 字正文 | 返回长度 | `subagent.result_granularity` |
| P4 | 关闭后续跑同一 agent，追问暗号 | 是否记得 | `subagent.resume` |
| P5 | 指定越界写共享文件 | 是否被宿主拦截 | `fs.guard` |
| P6 | 子代理自报 `$PID` 与宿主 pid | 是否相同 | `isolation.process` |

规则：

1. 探测一律使用临时目录，**不得触碰项目源码**
2. 首次探测属于**成本操作**（P2 是主要开销），执行前需用户确认
3. 结果缓存；只有**宿主版本或模板结构版本**变化才重测
4. 探测失败（含被权限策略拒绝）如实记为 `unknown`，不猜测
5. **探测全程由 Agent 执行，不需要脚本**：Agent 按 P1-P6 逐条执行、记录并写档案；安装器只复制文件，不参与探测
6. **「自动重测」= 档案有效性检查**：比对档案里的 `schema_version`（模板结构版本）、`host_version`、探测项清单；任一不一致即提示用户三选一（立即重测 / 暂用旧档案 / 其它）
7. 档案内容与探测结果**是同一份东西**：预置实测值、引导式探测、用户自填，只是三种来源，最终都落到同一个档案文件

### 4.4 降级矩阵

| 能力缺失 | 后果 | 处理 |
|---|---|---|
| 无 subagent 工具 | L4 无法执行 | 只跑 L0-L3；或改用（待定的）加固层执行器 |
| 无 shell | 无法验证、无法提交 | **不支持**（明确拒绝，不降级） |
| 无文件写 | 回执/契约无法落盘 | **不支持**（明确拒绝） |
| `max_concurrency` 未知 | 可能硬失败 | 按 **1** 处理（退化为串行） |
| 无 `resume` | — | 不影响：默认就是每轮新 spawn |
| 无背景通道 | 无法中途唤醒 | 只允许「单次 spawn 内可完成」的任务粒度 |
| 无 git | 台账照常，提交由用户执行 | 显式提示 |
| `fs.guard = no` | 越界无事前拦截 | 强制事后扫描 + 声明可信度等级 |

## 5. 协议与数据面

### 5.1 目录结构

```
.parallel-agent/
├── 能力档案.md              # 可选：项目级覆盖项（宿主能力在全局）
├── 分流卡/                  # L1+ 的入口判定（含强拆条件核对）
├── 单轨/
│   ├── 任务卡/              # L2/L3 任务卡
│   └── 台账/YYYY-MM.md      # 单轨台账（只追加）
├── 契约/                    # 多轨：每轨每轮一份
├── 转达/                    # 仲裁者→轨道的派发信号（仅指针）
├── 回执/                    # 轨道自写
├── 快照.md                  # 仲裁者汇总与实检结果
└── 交接手册/                # 冷启动与跨会话交接
```

### 5.2 文件类型与必备字段

| 文件 | 落笔权 | 必备字段 |
|---|---|---|
| 分流卡 | 仲裁者 | 模式、依据、未知项、必产、下一步 |
| 任务卡 | 仲裁者 | 目标、非目标、未知项、假设、候选方案、验收 |
| 契约 | 仲裁者（须落盘后才派发） | `track` / `round` / `contract_version` / `scope.paths` / 暗号或校验点 / 红线 / 回执路径 |
| 转达 | 仲裁者 | 仅含轨道号 + 轮次 + 文件指针，**不含任务内容** |
| 回执 | **轨道自写** | `track` / `round` / 依据版本 / 产物路径 / 自检 / 未决 |
| 快照 | 仲裁者 | 各轨状态、实检结果、越界扫描结果、待处理项 |

### 5.3 身份外化

轨道身份不靠「会话还记得」，而是：

- `track`：契约/回执头部字段
- `round`：轮次编号
- `contract_version`：本轮依据的契约版本，产物与回执都要引用
- `scope.paths`：领地边界，越界校验的唯一依据

## 6. 执行器

### 6.1 执行器接口（纯文本契约，不写代码）

四个动作，任何执行器都必须能表达：

| 动作 | subagent 执行器 | 加固层执行器（待定） |
|---|---|---|
| `open` | 一次 `Agent` 调用（带契约路径） | `/new` + 名字注入 |
| `dispatch` | spawn 时 prompt 内给文件指针 | `/dispatch` 注入指针 |
| `collect` | spawn 返回值（一行指针） | 回执文件 + `/watch` |
| `close` | 执行结束即关闭 | `/delete` |

### 6.2 subagent 执行器（默认）

流程：

1. 读全局能力档案（`~/.parallel-agent/能力档案/<host>.md`），存在项目覆盖时合并 → 得到 `cap` 与 `max_concurrency`
2. 按轨切分契约，校验 `scope.paths` 互不相交
3. **分批**：`batch = min(轨道数, cap)`，逐批 spawn，超限不让它硬失败
4. 每条轨 prompt 只给：契约绝对路径 + 回执路径 + 返回格式（一行指针）
5. 收齐后：越界扫描 → 实检 → 落快照 → 统一提交

### 6.3 加固层执行器（待定）

加固层（进程隔离、单轨围观/中断、崩溃重建、中途唤醒）**整体列为待定**：一期不实现，先用 subagent 执行器跑真实项目，看实际体验后决定是否值得补。

若最终需要补，形态是**独立可选执行器**，不被默认路径依赖；未安装时 Skill 走降级分支。触发补做的信号：

- 真实项目里频繁出现「看不到轨道在做什么」或需要中止单轨
- 轨道数长期超过 `max_concurrency`
- 数据安全要求必须进程隔离

> 一期不实现，也不在安装链路中出现。

### 6.4 编排防坑规则（来自实测，强制）

| 规则 | 依据 |
|---|---|
| 单批 ≤ `max_concurrency`，超限自行分批 | Trae 实测第 6 个硬失败 |
| 轨道**禁止** `git add/commit`，提交由仲裁者统一做 | 并发 `index.lock` 风险 |
| 越界校验 = **scope 白名单 vs 实际文件集合扫描**；`git` 只作辅助 | `git` 对忽略目录/未跟踪文件失明 |
| 默认**不 resume**；每轮新壳 + 最新回执 | resume 残留已作废契约记忆 |
| 回执由轨道写文件，返回值只给**一行指针** | 防止主理人上下文被回执正文撑爆 |
| 任务粒度必须能在**单次 spawn** 内完成 | 无中途上报通道 |
| 契约头部必须写 `contract_version` | 产物可追溯到依据版本 |

## 7. Skill 与首次运行

### 7.1 三个 Skill

| Skill | 职责 | 是否依赖执行器 |
|---|---|---|
| `parallelagent-solo` | L0-L3 分流、任务卡、单轨台账 | 否 |
| `parallelagent-arbiter` | L4 决策、写契约、编排、实检、落快照 | 是（读能力档案选执行器） |
| `parallelagent-track` | 接收契约、执行、写回执 | 否（只认文件） |

### 7.2 首次运行流程

0. **档案有效性检查**（Skill 首次激活时与**每次 L4 预检**各做一次）：比对 `schema_version`、`host_version`、探测项清单与当前模板；不一致 → 提示三选一（立即重测 / 暂用旧档案 / 其它）
1. **安装后的首次对话，由 Skill 主动询问用户**（不擅自探测）：是否现在做初始化测试
2. 用户三选一：
   - **立即初始化测试**：说明预计 spawn 次数与成本 → 确认后执行 P1-P6 → 写全局档案
   - **触发 L4 时再测试**：先跳过；第一次 L4 时再走同一确认流程
   - **其它**：用户自由输入（例如改用指定路径的档案、改写已有档案、先不测等）；Skill 按用户输入执行，不擅自探测
3. 写全局档案（含 `probed_at` / `host_version` / **可信度声明** / 原始报错）
4. 按降级矩阵得出「本宿主可执行的最大模式」并告知用户
5. 之后每次 L4 只读档案，不再探测

### 7.3 跨宿主安装

统一格式：**单文件 `SKILL.md` + YAML frontmatter**，所有宿主共用同一份内容，不做别名或分叉。

| 宿主 | Skill 路径（示例） | 触发方式 |
|---|---|---|
| Trae CN | `~/.trae-cn/skills/` | 描述自动激活 |
| WorkBuddy | `~/.workbuddy/skills/` 或项目级 | 描述/命令 |
| Claude Code 系 | `.claude/skills/` | 描述自动激活 |

安装方式：**`npx` 一条命令**，复制三个 Skill、共享 reference、模板与能力档案模板，并打印首次运行提示（§7.2）。安装器只做文件复制与提示：零运行时依赖，不注册服务，不改宿主配置。

> 一期只验证 Trae CN。其它宿主可复制安装，但属「可装未验证」：装上后按能力档案降级运行，缺 subagent / shell / 文件写则明确拒绝，不做猜测性兼容。

### 7.4 安装器职责与升级策略

安装器（`npx`）只做「文件复制 + 安装状态 + 提示」，**不探测、不写能力档案、不碰项目目录**。

**两类文件，两种归属：**

| 文件 | 归属 | 格式 | 内容 |
|---|---|---|---|
| `能力档案.md` | **Agent 写**；CLI 不写 | Markdown + frontmatter | 探测结果、`confidence`、原始报错、备注 |
| `install-state.json` | **CLI 写**；Agent 不写 | JSON | 安装版本、宿主类型、目标路径、各文件校验和、安装时间 |

> 不合并成一个文件：否则 CLI 与 Agent 都写同一份状态，等于制造第二个事实源。

**升级覆盖策略：**

| 对象 | 行为 |
|---|---|
| 产品文件（skills / references / templates） | **全量覆盖**；若校验和与 `install-state.json` 不符（用户改过），写 `<file>.new` 并提示，不静默丢弃改动 |
| `能力档案.md` | **永不覆盖**；版本不符由 Agent 走 §7.2 的三选一 |
| 项目 `.parallel-agent/` | **永不触碰** |
| 重复执行 `init` | 幂等；未变更文件跳过，变更文件按上表处理 |

## 8. 与 v2 的差异

| 项 | v2 | v3 |
|---|---|---|
| 执行器 | CDP 插件（必需） | subagent（默认）/ 加固层执行器（待定） |
| 运行时服务 | HTTP 网关 9318 | 无 |

## 9. 迁移路径

1. **协议先行**：把 v2 的契约/回执/快照/台账模板原样迁入 v3，只补 `contract_version` 与身份字段
2. **Skill 改写**：仲裁者去掉全部 CDP 调用段落，改为「读档案 → 分批 spawn → 扫描 → 快照」
3. **能力档案落地**：先手工填一份 Trae 的实测值（并发 5、nested=no、resume=yes、guard=no），跑通一轮 L4
4. **加固层**：暂不迁移，列为待定；真实项目体验后若确有需要，再作为独立可选执行器接入
5. **验证**：先用「subagent 执行器」跑同一任务；可选执行器落地后再做两者对照

## 10. 决策记录

| 问题 | 决策 |
|---|---|
| 能力档案放哪 | **全局，每宿主一个文件** `~/.parallel-agent/能力档案/<host>.md`；项目级只放覆盖项 |
| 首次探测由谁触发 | **安装后首次对话由 Skill 询问用户**，三选一：立即初始化测试 / 触发 L4 时再测试 / 其它（用户自由输入） |
| 是否提供安装器 | **提供 `npx` 一条命令安装**；只做文件复制与提示，零运行时依赖 |
| 加固层是否自建 | **列为待定**，一期不实现；看 v3 实际体验后决定是否补 |
| 多宿主 skill 格式 | **统一 Markdown + YAML frontmatter**，全宿主同一份内容 |
| 探测结果的可信度 | **写进能力档案**（`confidence: 实测 / 自述 / 未验证`），降级决策以最低可信度为准 |
