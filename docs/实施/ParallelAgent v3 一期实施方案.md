# ParallelAgent v3 一期实施方案

- 状态：草案（待评审）

- 上游设计：[ParallelAgent v3 方案设计](../设计/ParallelAgent%20v3%20方案设计.md)、[ParallelAgent v3 生命周期治理方案](../设计/ParallelAgent%20v3%20生命周期治理方案.md)
- 验证宿主：Trae CN（一期只验证这一个；协议本身保持宿主中立）

---

## 0. 一期要交付什么

**一句话**：一套纯文本的协议 + 模板 + 三个 Skill，在 Trae CN 上跑通「L0-L3 单轨」与「L4 三轨并行」全链路，人工填写能力档案，不写任何可执行代码。

**判定标准**：能在一个真实小项目上完成一次三轨并行改造，产物、回执、快照、台账全部落盘，仲裁者通过文件完成实检，全程无插件、无 HTTP 服务。

---

## 1. 范围

### 1.1 一期做

| 项 | 内容 |
|---|---|
| 协议 | 分流卡、任务卡、台账、契约、转达、回执、快照、交接手册的字段与校验规则 |
| 模板 | 上述八类文件的空白模板 |
| Skill | `parallelagent-solo` / `parallelagent-arbiter` / `parallelagent-track` |
| 共享 reference | `分流.md` / `台账.md` / `协议.md` |
| 能力档案 | 模板 + Trae CN 预置实测值 + 引导式探测流程（三种来源填同一份档案）+ 档案有效性检查，含 `schema_version` 与 `confidence` |
| 执行器 | 仅 subagent（宿主原生），分批 ≤ 5 |
| 安装器 | `npx` 一条命令：复制 Skill / reference / 模板 / 档案模板，打印首次运行提示 |
| 验证 | 单轨 L0-L3、三轨 L4、越界注入、失败重跑、冷启动接管 |

### 1.2 一期不做

- 以脚本或服务形式提供探测（不需要：探测全程由 Agent 按步骤执行）
- 自动分批 / 自动重试策略
- 新任仲裁者自动拉起
- 加固层执行器（进程隔离 / 围观 / 中断 / 崩溃重建）——**整体待定**
- 多宿主**验证与预置档案**（一期只验证 Trae CN；其它宿主可复制安装，但属「可装未验证」）
- 工作区级覆盖文件（留接口，不实现）

## 3. 工作分解

### W1 协议与模板（无代码）

| 产出 | 内容要点 | 完成判据 |
|---|---|---|
| `references/协议.md` | 八类文件字段表；落笔权；命名规范；越界扫描算法；契约版本规则 | 字段表覆盖设计文档 §5.2 全部条目；扫描算法有伪代码级步骤 |
| 八份模板 | 每份含固定头部字段与「填写说明」 | 模板字段与协议一致，无多余必填项 |
| `references/分流.md` | L0-L4 判据、强拆条件、必产清单 | 与 v2 判据对齐，去掉插件相关步骤 |
| `references/台账.md` | 单轨台账 ID 规则、只追加、commit 回填 | 可被 doctor 式人工检查 |

关键规则（写进协议，不靠 Skill 各自复述）：

1. 契约头部必含 `track` / `round` / `contract_version` / `scope.paths` / 回执路径
2. 回执由轨道写，返回值只允许一行指针
3. 越界扫描 = `scope` 白名单 vs 实际新增/修改文件集合；`git` 仅辅助，不作为唯一依据
4. 轨道禁止 `git add/commit`，提交统一由仲裁者执行
5. 默认不 resume；重跑 = 新 spawn + 最新回执

### W2 Skill 三件套

统一格式：**每份 Skill 是单文件 `SKILL.md` + YAML frontmatter**（`name` / `description` / `version`），全宿主同一份内容，不做分叉。

| Skill | 一期职责 | 完成判据 |
|---|---|---|
| `parallelagent-solo` | L0-L3 分流、任务卡、单轨台账 | 能在无 `.parallel-agent/` 的项目里正确分流并落台账 |
| `parallelagent-arbiter` | 读能力档案 → 写契约 → 分批 spawn → 扫描 → 快照 → 统一提交 | 一次三轨任务可全自动走完，不依赖插件 |
| `parallelagent-track` | 只认契约文件，执行一次，写回执，返回一行 | 同一契约重复执行结果一致（幂等） |

仲裁者 Skill 必须包含的硬规则：

- 批次 `batch = min(轨道数, max_concurrency)`；超限不交给宿主排队
- 每条轨 prompt 只给契约路径 + 回执路径 + 返回格式
- 收齐后先扫描再实检，越界 ≥1 立即收回该轨
- 写快照后才允许提交

### W3 能力档案（人工）

| 产出 | 内容 |
|---|---|
| `hosts/能力档案-模板.md` | 设计文档附录 A 的字段，留空可填 |
| `hosts/trae-cn.md` | 预置实测值：`max_concurrency: 5`、`nested: no`、`resume: yes`、`sandbox.shell: yes`、`sandbox.fs_write: yes`、`fs.guard: no`、`isolation.process: in-process`、`vcs.git: yes` |

- 安装位置：`~/.parallel-agent/能力档案/trae-cn.md`（全局），一期不做项目覆盖
- 档案里必须写 `probed_at`、`host_version`、`schema_version` 与 `confidence`（可信度声明），便于升级后失效、降级时取保守值
- **档案有效性检查**（由 Agent 读取比对，不写脚本）：Skill 首次激活与**每次 L4 预检**各做一次；`schema_version` / `host_version` / 探测项清单任一不一致 → 提示三选一（立即重测 / 暂用旧档案 / 其它）
- L0-L3 不做校验

三种来源，产出同一份档案：

| 来源 | 适用 | 优先级 |
|---|---|---|
| 预置实测值（`hosts/trae-cn.md`） | 已测过的宿主 | 最高：直接复制到全局档案，标 `confidence: 实测` |
| 引导式探测 | 新宿主 / 宿主升级 | 次之：Agent 按 P1-P6 逐条执行，标 `实测` |
| 用户自填 / 指定已有档案 | 用户偏好、离线环境 | 以用户输入为准，按实际来源标 `自述` 或 `未验证` |

### W4 验证（一期验收）

| 编号 | 用例 | 判定 |
|---|---|---|
| V1 | L0 单文件改动 + 台账 | 台账有 ID、证据、结论；diff 只含目标文件 |
| V2 | L2 探路 | 产出任务卡，不写业务代码 |
| V3 | L4 三轨并行 | 三份契约、三份回执、一份快照；越界扫描无命中；测试通过 |
| V4 | 越界注入 | 故意让一轨写 scope 外文件，扫描必须命中并收回 |
| V5 | 失败重跑 | 一轨首次失败，按最新契约重跑后结果一致 |
| V6 | 冷启动 | 新会话读交接手册，能说清阶段、欠账、重跑方式 |
| V7 | 并发上限 | 6 轨时第 6 个失败，改 5+1 分批后全部完成 |

V3 与 V4 是必须项；V5-V7 允许在二期补测，但方案里必须写明预期行为。

### W5 安装器（npx 一条命令）

| 项 | 要求 |
|---|---|
| 命令形态 | Skill：`npx skills add YorickFin/ParallelAgent -g -a agents`；共享数据：`npx parallelagent@latest init` |
| 动作 | CLI 只复制 3 份 reference、8 份模板、能力档案模板到 `~/.parallel-agent/`；不安装 Skill、不建链接、不删除文件 |
| 安装状态 | 写 `install-state.json`（安装版本、数据目录、各文件校验和、安装时间）；**CLI 独有，Agent 不写** |
| 升级覆盖 | 产品文件**全量覆盖**；若校验和与 `install-state.json` 不符（用户改过），写 `<file>.new` 并提示；**能力档案与项目 `.parallel-agent/` 永不覆盖** |
| 首次提示 | 安装结束时打印 §7.2 的三选一提示（立即初始化 / 触发 L4 时再测 / 其它：用户自由输入），**不代替用户做选择** |
| 边界 | 不探测、不写能力档案、不碰项目目录 |
| 约束 | 零运行时依赖；不注册服务；不改宿主配置；重复执行幂等 |
| 完成判据 | 新机器上跑两条命令即可完成安装；`--help` 与重复执行均正常 |

## 4. 实施顺序

按依赖排，不并行推进：

1. **协议先行**：先写 `references/协议.md` 与八份模板（W1）。它是 Skill 的输入，写反了后面全返工。
2. **能力档案**：`hosts/trae-cn.md` 填人工实测值（W3）。仲裁者 Skill 需要它。
3. **track Skill**：先做最简单的一环（只认契约），用沙箱契约验证幂等。
4. **arbiter Skill**：接档案、分批、扫描、快照。
5. **solo Skill**：与 L4 解耦，可独立完成；建议此时补齐。
6. **安装器**：链路跑通后再做 npx 安装，避免把未定型目录固化进安装脚本。
7. **验收**：V1 → V2 → V3 → V4，逐项过。

一期先不追求「多宿主验证」，先把 Trae 上的一条链路打穿。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 协议写得太细，Skill 变成抄协议 | 维护双份，易漂移 | 协议只定义字段与校验，流程写 Skill；Skill 引用协议不复制 |
| 越界扫描在大仓库变慢 | 每轮耗时 | 一期限定「本轮新增/修改文件」集合，不做全量树扫描 |
| 并发 5 太小，三轨项目无感 | 看不出收益 | V3 用三轨是刻意的；二期再验证 5 轨上限 |
| 仲裁者上下文被回执撑爆 | 多轨时先爆 | 强制一行指针 + 回执落盘；V3 观察上下文增幅 |
| 无自动探测导致换宿主成本高 | 可移植性打折 | 一期只验证 Trae；档案模板保证二期可脚本化 |
| 交接手册写得太厚 | 冷启动反而变慢 | 手册只写结构性结论 + 重跑方式，过程留在回执 |

## 7. 一期完成的标准

以下全部满足才算一期完成：

- [ ] `references/协议.md` + 8 份模板就位，字段与设计文档一致
- [ ] 三个 Skill 就位，且彼此不重复协议正文
- [ ] `hosts/trae-cn.md` 已填实测值，含 `probed_at`、`host_version`、`schema_version` 与 `confidence`
- [ ] 档案有效性检查生效：版本不一致时能提示三选一，而不是静默沿用
- [ ] `install-state.json` 记录安装版本与文件校验和；升级时用户改过的文件不被静默覆盖
- [ ] `npx parallelagent@latest init` 可一条命令完成安装，且打印首次运行提示
- [ ] 在真实项目完成一次 L0 与一次 L4 三轨任务
- [ ] 越界注入用例命中，并按规则收回该轨
- [ ] 一次冷启动接管成功（新会话读手册后能继续）
- [ ] `test-docs/报告/` 有一份完整测试报告，含证据路径
